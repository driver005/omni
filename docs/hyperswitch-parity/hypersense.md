## Not ported
- Database-backed identity lookup: `find_active_user_by_user_id(&token.user_id)` supplies authoritative `name`/`email` (external_service_auth.rs:85-100). C++ fabricates `Hypersense User` / `hypersense+<hash>@example.com` and only overrides from cache (cppm:63-65, 136-146).
- Persistent blacklist store: `insert_user_in_blacklist` / `check_user_in_blacklist` (external_service_auth.rs:59-61, 77-81). C++ uses cache keys `hypersense.blacklist.<user>` (cppm:131, 189-192).
- Blacklist check honors token `exp`: upstream `check_user_in_blacklist(&state, &user_id, token.exp)` (external_service_auth.rs:78). C++ only tests cache `.hit`, ignores expiry (cppm:131).
- Config-driven token signing: `ExternalToken::new_token(user_id, merchant_id, &state.conf, service_type)` (external_service_auth.rs:29-35). C++ hardcodes secret `hypersense-jwt-secret` and self-builds the payload with a fabricated `jti` (cppm:69-79).
- Dashboard auth semantics: `DashboardNoPermissionAuth` with `allow_connected:false, allow_platform:false` and no named permission (hypersense.rs:28-31). C++ substitutes `AppPermission::ADMIN` (cppm:36). `allow_platform`/`allow_connected` flags expressed but not equivalent (cppm:37-38).
- Service-type validation against typed `ExternalServiceType::Hypersense` and `check_service_type` (external_service_auth.rs:83; hypersense.rs:25, 72). C++ compares literal string `"Hypersense"` (cppm:127).
- Response shape: upstream signout returns bodyless `StatusOk` (external_service_auth.rs:63); C++ emits a JSON body (cppm:197). Verify uses typed `ExternalVerifyTokenResponse` variant (external_service_auth.rs:96) vs hand-written JSON (cppm:151-158).
- Flow/error plumbing: upstream routes use `Flow::{HypersenseTokenRequest, HypersenseVerifyToken, HypersenseSignoutToken}` and `api_locking::LockAction::NotApplicable` (hypersense.rs:15, 42, 62, 32, 52, 76). C++ only records metrics counters (cppm:90-91, 148-149, 194-195); no locking/flow error semantics.

## Implementation disposition
- Database-backed identity lookup — IMPLEMENTED — `repository().find_user_by_string(claims->user_id)` + `get_status() != "active"` rejection, name/email from persisted record (cppm:230-235).
- Persistent blacklist store — SUBSTITUTED — `repository().set_config`/`get_config` under `hypersense.blacklist.<user>` gives persistent storage, with a cache TTL mirror for other local handlers (cppm:22, 293-299, 380-391); config key-value stands in for upstream dedicated blacklist table (external_service_auth.rs:59-61).
- Blacklist check honors token `exp` — IMPLEMENTED — `is_blacklisted(claims->user_id, claims->exp)` compares `blacklisted_at > (exp - kExternalTokenTtlSeconds)` (cppm:217, 374-392); mirrors `check_user_in_blacklist(&state, &user_id, token.exp)` (external_service_auth.rs:78).
- Config-driven token signing — IMPLEMENTED — `signing_secret()` resolves `repository().get_config("hypersense.jwt_secret")` with default fallback (cppm:23-26, 363-372), payload carries real `uuid_v4` jti and TTL const (cppm:148-155); HMAC `JwtSigner` matches upstream `jwt::generate_jwt` (jwt.rs:50-55) but is a local crypto backend.
- Dashboard auth semantics — DEFERRED — handler delegates to the audited registry (cppm:113-120), but registry.cppm:148 still encodes JWT + `AppPermission::ADMIN` with allow flags true/true; upstream needs `DashboardNoPermissionAuth` false/false and no permission (hypersense.rs:28-31). Registry row change is shared-file work outside this lane.
- Service-type validation — SUBSTITUTED — typed `ServiceTypeValidator` parses to `ExternalVerifyTokenResponse::Hypersense` and is enforced at cppm:222 (cppm:74-98); stands in for upstream typed `ExternalServiceType::Hypersense` + `check_service_type` (authentication.rs:6851-6863).
- Response shape — SUBSTITUTED — signout emits bodyless `send_status_ok` matching upstream `StatusOk` (cppm:306, 477-485); verify emits the local typed `HypersenseVerifyResponse` via serde with the four upstream fields (cppm:36-70, 241-246) because the DTO variant is an empty enum marker (cppm:28-34).
- Flow/error plumbing — SUBSTITUTED — `metrics().record_flow(...)` + per-route counters for all three flows (cppm:170-171, 238-239, 302-303); upstream `LockAction::NotApplicable` acquires no lock, so no lock gap; typed `Flow` enums are represented as flow-name strings.

No justified external-dependency STUB remains: the former Persistence STUB is closed by repository-backed user/config access; the remaining deviations are documented local substitutes (config store, HMAC `JwtSigner`, flow-name strings) plus the DEFERRED shared-file auth registry row.
