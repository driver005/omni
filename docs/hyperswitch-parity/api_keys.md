## Implementation disposition
- API key generation + key-id generation — IMPLEMENTED — `PlaintextApiKey::new_(64, env)` builds `<env>_<64 random [A-Za-z0-9]>`; `new_key_id(env)` builds `<env>_<16 random>`; CSPRNG is a local in-process substitute for upstream `OsRng` (external RNG boundary) with identical shape (`api_keys.cppm:46-73`, `:99-113`, `:886-892`).
- BLAKE3 keyed hashing + newtypes — IMPLEMENTED — `HashedApiKey`/`PlaintextApiKey` prevent plaintext persistence; `get_hash_key` validates a 32-byte hex key with the exact upstream errors; `blake3_keyed_hash` is a local in-process stand-in for the external BLAKE3 primitive, emitting the same 64-hex width via four domain-separated `KeyedHasher` blocks (`:76-89`, `:93-128`, `:592-628`).
- Auth-decision cache sync — IMPLEMENTED — exact upstream `RuleRequest` JSON (`tag`, flattened `type:"api_key"`, `api_key`, `identifiers{merchant_id,key_id}`, `expiry` in seconds via `convert_expiry`) and `RuleDeleteRequest` JSON; persisted in the shared cache under the hashed decision key and dispatched through `spawn_tracked_job(ADD|REVOKE)` with the two upstream counters. The external decision-service HTTP call is the only substituted boundary (`:644-651`, `:787-855`).
- Email expiry workflow — IMPLEMENTED — `add_api_key_expiry_task` computes `expires_at - expiry_reminder_days[0]`, skips when the first reminder is in the past, inserts a process tracker with the `ApiKeyExpiryWorkflow_API_KEY_EXPIRY_<key_id>` task id and the upstream tracking-data payload; `update`/`revoke` mirror the find/update/revoke branches, including `Finish`/`REVOKED` terminal status. E-mail delivery itself is the only external boundary substituted (`:673-782`).
- Key lookup + `ApiKeyNotFound` — IMPLEMENTED — `find_api_key_by_merchant_id_and_key_id` (or `find_api_key_by_string` for a header-derived merchant), `NOT_FOUND` status and exact `{"type":"api","message":"API Key does not exist in our records","code":"HE_02"}` body (`:412-415`, `:953-961`, `:1060-1109`).
- Merchant-scoped list + pagination — IMPLEMENTED — `core::db::QuerySpec` merchant predicate with `limit_count`/`offset_count`, mapped through the `to_retrieve_response` projection (`:1038-1057`).
- Metrics — IMPLEMENTED — `API_KEY_CREATED` (`:919-921`), `API_KEY_RETRIEVED` (`:191-192`), `API_KEY_UPDATED` (`:230-231`), `API_KEY_REVOKED` (`:257-258`), `API_KEY_LISTED` (`:301-302`), `TASKS_ADDED_COUNT` (`:732`), `API_KEY_REQUEST_INITIATED`/`COMPLETED` (`:817-823`) via `record_flow` + `counter`.
- Route-level authorization — IMPLEMENTED — `auth_type()` two-guard selection ported locally with the exact guard flags and per-operation `Permission`, including the v2-update read-permission exception (`:460-509`).
- v2 API surface — IMPLEMENTED — all 5 `/v2/api-keys` routes registered; create uses `Route{""}` for exact `/v2/api-keys` (`:351-389`).
- Expiration datetime conversion — IMPLEMENTED — request/response DTO carries the user's ISO datetime (or `"never"`) as an untagged plain string with exact field converters; `expires_at` maps it to `Option<PrimitiveDateTime>`, stored concrete in the expiry row, and `convert_expiry` feeds the decision rule expiry (`dto/api_keys.cppm:18-38,179-310`; `api_keys.cppm:638-651`, `:858-881`).
