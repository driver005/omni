## Module-level notes

- Both Ghost routes are Admin-only (`admin/routes.js:51-52`). The members/web comments router (`web/comments/routes.js:52-92`) is a separate controller (`api.commentsMembers.*`, exported at `api/endpoints/index.js:331-333`) and is out of scope; it does not bind `comment-replies.js`.
- Shared Ghost service: `commentsService` is `services/comments` (`comment-replies.js:3`). Both ops go through `CommentsController` (`comments-controller.js:18-26`) into `CommentsService`; read uses `getCommentByID` (`:780-784`), browse uses `getAdminReplies` (`:709-718`) → `getReplies` (`:700-707`). Both depend on `checkEnabled()` (`comments-service.js:174-180`) and `#withImpersonationContext` (`comments-controller.js:57-73`).
- Neither Ghost op emits side effects (no events, mail/outbox, webhooks, jobs); `X-Cache-Invalidate` is only set by mutating ops (`comments-controller.js:211-225`), and both controller entries explicitly disable cache invalidation (`comment-replies.js:27-29,54-56`). C++ counterparts likewise have no side effects or cache usage.
- C++ middleware chain for both routes: `content_type_middleware` + `require_auth` at `/comments` router (`discovery/comments/routes.cppm:19-21`; `middleware/auth.cppm:12-29`), plus a redundant inline token check in each handler (`read_by_id/handler.cppm:21-25`, `comment_replies/handler.cppm:21-25`). Handlers use a local workflow driver (`LocalWorkflowDriver`, `handler.cppm:17`) with one `ExecuteStep`; registration in `all.cppm:40-41,411-412`.
- Not EXTRA: the sibling C++ routes on `discovery/comments/routes.cppm:21-113,144-179` (browse, create, edit, destroy, likes, dislikes, reports, post detail) have Ghost counterparts in `comments.js`, `comment-likes.js`, `comment-dislikes.js`, `comment-reports.js`, and `comments-members.js` — they are not extras of `comment-replies.js`.
- Cross-cutting residual gaps (whole comments service, not route-specific): real Knex transactions and `FOR UPDATE` locking (`comments-service.js:201-212,236-238`), permission services, member-session/impersonation, Tinybird/SMTP notifications, and real `findPage` pagination have no C++ primitive; C++ substitutes an in-memory `ctx.store().json_for("comments", …)` and locally computed pagination.
