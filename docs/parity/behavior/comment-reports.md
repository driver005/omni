## Route details

### GET `/comments/:id/reports` — PARTIAL

**Ghost** (facts 1–8):

1. **Identity.** Admin API GET `/comments/:id/reports` registered on the admin router with middleware `mw.authAdminApi` and handler `http(api.commentReports.browse)` (`admin/routes.js:53`). Router-level `router.use(apiMw.cors)` applies to all admin routes (`admin/routes.js:17`). No labs flag on this route.
2. **Operation.** Controller key `browse`, `docName: 'comment_reports'` (`comment-reports.js:5-8`). No `data`/body shape. - **Divergence — output field set:** Ghost embeds `member` via `withRelated:['member']` (`comments-service.js:731`); C++ requests `include=member` but `embeddings()` ignores it (`context_context.cppm:1646-1663`), so no member object.
- **Divergence — auth:** Ghost `mw.authAdminApi` + `permissions`; C++ stacks `content_type_middleware` + `require_auth` with no `bearer_middleware` (`routes.cppm:19-21`) and ALSO has an inline 401 `{"error":"Unauthorized"}` (`handler.cppm:21-25`) that differs from the middleware's `UnauthorizedError` envelope (`auth.cppm:19-26`). - **Divergence — input validation:** Ghost `ValidationError` with 24-hex/`me` id format and global `page`/`limit` format checks (`validators/input/all.ts:26-29,46-60`); C++ only checks non-empty id and uses `std::stoul` with silent fallback for page/limit (`execute.cppm:21-24,66-70`).
- **Agreement:** verb/path, 200/404/422 status semantics, `{comment_reports,meta.pagination}` envelope, no `X-Cache-Invalidate` header, no response cache.

## Module-level notes

- `comment-reports.js` is a single-operation controller (`browse`) with `docName 'comment_reports'` but permissions borrowed from `comments` (`comment-reports.js:7,21-23`) — a deliberate cross-resource permission override.
- Only one Ghost route binds it (`admin/routes.js:53`); no members-app/content route. The C++ `discovery/comments/report/` POST `/comments/:id/report` handler (`discovery/comments/report/workflow/step/execute.cppm:25`) implements Ghost's separate "report a comment" custom action from `comments.js`, not this controller — not counted as EXTRA here.
- Shared C++ middleware chain (`content_type_middleware`, `require_auth`, `token()`) is identical to sibling discovery comment routes (`discovery/comments/routes.cppm:19-21`); `bearer_middleware` is available (`middleware/base.cppm:3-7`) but not installed on this router.
- The fabricated-report fallback and store-backed "existence" check are shared patterns with `discovery/comments/comment_likes/`, `comment_dislikes/`, `like/`, `dislike/` steps (e.g. `comment_likes/workflow/step/execute.cppm:25,38-42`), so the divergence is systemic, not local to this handler.
