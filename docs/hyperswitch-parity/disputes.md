## Local in-process substitutes (allowed by the task)
These replace external infrastructure only; the surrounding upstream logic, shapes, flags, errors, guards and persistence are exact.
- Connector execution, Dsync `sync`, UCS routing and `execute_dispute_gateway`: `app::connector::ConnectorRouter` (`call_connector` `disputes.cppm:1651`, `execute_dispute_gateway` `:1643`).
- Outgoing webhook delivery: `EventBus` + `WebhookDeliveryService` (`notify_dispute` `disputes.cppm:1705-1721`).
- Process tracker scheduling: `ProcessTrackerService` with upstream task names/tags (`disputes.cppm:1592-1629`).
- File store and evidence persistence: `save_file` + `config_store` keyed by dispute id (`disputes.cppm:1366-1400`, `:1517-1543`).
- Multipart upload: the local HTTP layer carries JSON (`EvidenceUploadWire`), normalized to the same `CreateFileRequest` fields upstream derives from the multipart parts.

## Shared contract requests
These need changes outside this module's edit scope; they are recorded here rather than silently worked around.
- `core/error`: `AppError` serializes as `{"error":KIND,"message":TEXT}` (`core/error/error.cppm:45-57`) and `AppErrorStatus` maps `PRECONDITION_FAILED` to CONFLICT (`:75`). Upstream `DisputeNotFound`/`DisputeStatusValidationFailed`/`InvalidDataFormat`/`Unauthorized` use `ApiError` shapes and statuses (404/400/422/401). To reach byte-identical error responses, the shared error layer needs upstream `ApiError` wire mapping. The handler currently supplies the exact upstream messages/kinds and statuses.
- `app/auth/registry.cppm`: dispute rules use a single `DISPUTE_READ` permission for all 15 ops (`:27,40,105,121,139-142,163,375-379,413`). The handler bypasses that via a locally constructed rule plus the exact upstream permission-name check (`disputes.cppm:789-826`), but a shared request to add `ProfileDisputeRead/Write` + `MerchantDisputeRead` and the connected/platform flags would let the registry express upstream auth directly.
- `app/store/domain_records.cppm` `DisputeRecord` (`:13-55`) lacks `attempt_id`, `connector_dispute_id`, `connector_status`, `merchant_connector_id`, `evidence`, `additional_details`. The handler stores these in `ConfigStore` as the local in-process persistence substitute; extending the store record would remove that indirection.
- `core/database`: no `GROUP BY` primitive, so `get_dispute_status_with_count` is a DB fetch + in-process count (`disputes.cppm:1444-1471`).
- `app/http`: JSON-only request bodies; a multipart reader would let `attach_evidence` consume the exact upstream multipart fields instead of `EvidenceUploadWire`.
