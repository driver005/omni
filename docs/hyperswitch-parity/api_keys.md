## Implementation disposition
- API key generation + key-id generation — SUBSTITUTED — builds `sk_`+uuid_v4 plaintext in `SecretString`, id from `ids().api_key_id()`, 12-char prefix; no env prefix/`API_KEY_LENGTH` (`api_keys.cppm:55-62`, `:119`).
- BLAKE3 keyed hashing + newtypes — SUBSTITUTED — `KeyedHasher{configured_hash_key()}.hash_with_domain(ApiKey)` + `SecretString` newtype; BLAKE3 hidden behind local crypto abstraction, key from `secret_resolver` with fallback (`api_keys.cppm:56-61`, `:568-575`).
- Auth-decision cache sync — SUBSTITUTED — `sync_decision_cache` puts/erases `api_keys.decision.<hash>` in generic cache on create/update/revoke; not the auth-middleware decision store (`api_keys.cppm:673-681`, `:98`, `:239`, `:287`).
- Email expiry workflow — SUBSTITUTED — `process_trackers().schedule("API_KEY_EXPIRY_REMINDER")` / `mark_terminal`, config `reminder_days`, `TASKS_ADDED_COUNT`; deterministic local tracker workflow, no email (`api_keys.cppm:619-656`, `:593-617`, `:100`, `:233-236`, `:286`).
- Key lookup + `ApiKeyNotFound` — IMPLEMENTED — `find_api_key` uses `find_api_key_by_merchant_id_and_key_id` / `find_api_key_by_string` + `NOT_FOUND` on retrieve/update/revoke (`api_keys.cppm:658-671`, `:145-149`, `:187-191`, `:265-269`).

- Metrics — IMPLEMENTED — `record_flow` + counters `API_KEY_CREATED`/`RETRIEVED`/`UPDATED`/`REVOKED`/`LISTED`, `TASKS_ADDED_COUNT`, `API_KEY_EXPIRY_TASKS_CLOSED` (`api_keys.cppm:103-104`, `:151-152`, `:241-242`, `:289-290`, `:358-359`, `:636`, `:655`).

- v2 API surface — IMPLEMENTED — all 5 `/v2/api-keys` routes registered (POST, GET list, GET id, PUT id, DELETE id) (`api_keys.cppm:426-485`).
