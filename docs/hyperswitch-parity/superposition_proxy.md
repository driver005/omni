Request: add the two enum values + `AppPermissionName` wire names and update the nine registry rows.
2. **Shared error envelope** — upstream `ApiErrorResponse` serializes as `{"error":{"type","message","code"}}` with `InvalidRequestData→422/IR_06`, `AccessForbidden→403/IR_22`, `InternalServerError→500/HE_00` (`hyperswitch_domain_models/errors/api_error_response.rs:586-590, 643-645, 58-60`; `api_models/errors/types.rs:13-19, 37-57`). The handler reproduces this exactly and locally (`cppm:2060-2120`). If a shared error type is introduced, delegate `api_error_wire`/`api_error_status` to it.
3. **Real Superposition SDK link** — the external Superposition SDK is external infra; the in-process `send_with` overloads (`cppm:1358-1654`) and local SDK-output structs (`cppm:1040-1349`) are the allowed substitute. When an SDK client is available in `AppContext`, replace only those overloads; converters, wire builders, validation, auth and error mapping are SDK-agnostic and unchanged.
4. **DTO wire embedding** — `include/app/dto/superposition_proxy.cppm` `PaginatedListResponse::data` is `vector<string>` (would double-encode) and `ResolveConfigResponse` serializes as `{"value":...}` rather than upstream `#[serde(transparent)]`. The handler builds both directly as `serde::Value` (`cppm:2031-2055`) so the wire is exact. If the shared DTO is migrated to `vector<serde::Value>` and a transparent resolver, the handler can switch from `wire_paginated`/`wire_resolve` to typed DTO encoding.
