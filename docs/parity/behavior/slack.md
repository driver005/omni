## Scope note

`slack.js` exports exactly one operation, `sendTest`, which does not touch a model/service directly: it emits the shared event `slack.test` (`slack.js:12-14`). The real work (outbound Slack webhook POST) lives in the `SlackPingService` listener (`docs/Ghost/ghost/core/server/services/slack-ping/slack-ping-service.ts:284-289,297-303`), booted via `services/slack-ping/index.ts:4-17`. The C++ counterpart is the only route bound to this controller; `include/blog/handlers/external/slack/` installs exactly `POST /slack/test` (`routes.cppm:19-31`), so there is no MISSING/EXTRA route for this module. The older `docs/parity/slack.md` describes a prior C++ state (`mutations.create("slack", body)`); current source writes an `outbox` record instead (`execute.cppm:16-18`) — this report uses current source. The 2026-11-20 strict-parity pass replaced that store write with a `slack.test` event on the registered `blog_handlers:outbox_shim` primitive, switched auth to the shared Ghost permission middleware, dropped the content-type gate, and made the success body `{}`; this report reflects that final state.
