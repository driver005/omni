## Module-level notes

- Controller `exports.js` has two operations under `docName 'exports'`: `download` (custom action) and `add` (`statusCode:202`). Both borrow permissions from `{docName:'db', method:'exportContent'}` (`exports.js:129-132,185-188`) — a cross-resource permission override, same pattern as sibling controllers.
- `SYNC_EXPORT_COMPONENTS = members, analytics, content, themes, routes` is the shared allowlist for the synchronous `download`/ZIP path; `ASYNC_EXPORT_COMPONENTS = [...SYNC, 'media']` is the allowlist for the async `add` path (`export-components.ts:1-10`). C++ mirrors both sets verbatim (`exports_download_get/.../execute.cppm:17-18`; `create/.../execute.cppm:35-36`); `media` appears only in the async/webhook path, never in the ZIP (comment at `export-components.ts:9`).
- Cross-route side effect: the C++ `create` step's `ctx.store().create("exports", …)` writes a context-local record that the `download` step reads back via `ctx.store().json_for("exports", …)` (`create/.../execute.cppm:62`; `exports_download_get/.../execute.cppm:41`). Ghost has no such coupling — `add` sends a webhook and `download` builds a ZIP from live services (`exports.js:86-110,195-198`). This in-memory `exports` resource is the stand-in for an async export-request queue and is context-local with `Ttl{}.never()` (`context_context.cppm:656-667`), so it is not a durable queue.
- Both C++ routes share the same router-level middleware chain (`content_type_middleware`, `require_auth`) installed once at `system/exports/routes.cppm:20-21`; the GET route's child `.add_route` inherits it. `require_auth` is the only auth primitive — `bearer_middleware` is not mounted on this router. Neither handler writes a real `core::cache::Cache` key; the only caching is indirect `ResourceStore` records tagged `resources` with never-expiry (`context_context.cppm:654,661-662`).
- No EXTRA C++ routes: `ExportsRoutes::install` registers exactly POST `/exports` and GET `/exports/download` (`system/exports/routes.cppm:19-40`), mapping 1:1 to `admin/routes.js:404-405`. No MISSING Ghost routes: both controller methods have exact path+verb counterparts.
- Header naming: Ghost `createStreamResponse` uses `Attachment; filename=...` with capital A (`stream-response.ts:46`); C++ uses `attachment; filename=...` (`exports_download_get/handler.cppm:27`). HTTP header values are case-insensitive keywords; effect is equivalent. (Superseded: the group-49 handler now uses Ghost's exact capital-`A` form and adds `Content-Type` / `Cache-Control`.)
