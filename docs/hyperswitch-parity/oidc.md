## Rows moved to MATCH
1. `GET /.well-known/openid-configuration` — was PARTIAL: root path restored; discovery document rebuilt per request from configured `tenant.base_url`/`user.base_url` (no ad-hoc cache), exact `OidcDiscoveryResponse` DTO and field values (`oidc.cppm:565-619`, `:856-866`, `:959-972`).
2. `GET /oauth2/jwks` — was STUB: replaced the synthetic hashed modulus/hardcoded `e="AQAB"` with a real in-module port of `extract_rsa_public_key_components` (PEM decode → DER PKCS#8/PKCS#1 parse → big-endian `n`/`e` → `Base64Url` no-pad encode), enumerating all configured keys and emitting one JWK per key (`oidc.cppm:238-324`, `:621-667`, `:1012-1033`). Verified against the embedded 1024-bit RSA PEM: derived `n` and `e="AQAB"` match `openssl rsa -modulus`/`-text`.
3. `GET /oidc/authorize` — was PARTIAL: query-only input with space/whitespace scope parsing; exact redirect-URI match and registered-client lookup (no auto-registration); `AccessDenied`/`UnauthorizedClient`/`InvalidScope`/`InvalidRequest` RFC wire errors; 32-char alphanumeric auth code; exact `AuthCodeData` payload; `build_oidc_redirect_url` equivalent; 302 with exact `RedirectionResponse` body (`oidc.cppm:670-753`, `:1058-1106`, `:1282-1296`).
4. `POST /oauth2/token` — was PARTIAL: form-only input; exact HTTP Basic `OIDC_CLIENT_AUTH` client-id/secret validation; RFC `invalid_request`/`invalid_client`/`invalid_grant` errors with `OI_XX`/`IR_51` codes; exact `IdTokenClaims`/`AccessTokenClaims` field order (removed `jti`/`typ`, added access-token `scope`, removed access-token `nonce`/`email_verified`, `preferred_username` from email); 900s/3600s TTLs; configured key material (`oidc.cppm:755-853`, `:1115-1169`, `:1212-1277`).

## Shared contract requests
- **SR-1 — `app::auth`: add an `OIDC_CLIENT_AUTH` scheme and register `oidc_token` with it.** Needed so route-level authorization (rather than the handler) performs HTTP Basic client-id/client-secret validation against `conf.oidc.client` (`authentication.rs:464-486`, `:573-599`). Current `registry.cppm:247` still maps `oidc_token` to `JWT`/`USER_WRITE`. Local workaround: `parse_basic_auth` + `configured_oidc_client` enforce the exact upstream check in `handle_oidc_token` (`oidc.cppm:761-788`, `:1141-1169`); the JWT rule is not consulted for this route.
- **SR-2 — `app::auth`: model upstream `auth_type(NoAuth, DashboardNoPermissionAuth{allow_connected,allow_platform}, headers)` for `oidc_authorize`** (`routes/oidc.rs:56-63`). Current registry only has `NO_AUTH` (`registry.cppm:245`). Local workaround: handler resolves the authenticated identity from the auth context/headers/bearer and returns `AccessDenied` when absent (`oidc.cppm:713-722`, `:1173-1189`).
- **SR-3 — `app::crypto::JwtSigner`: real RS256 JWS signing with `kid` in the protected header** (`services/encryption.rs:151-167`). The shared signer is a keyed-digest stand-in with `{"alg":"RS256","typ":"JWT"}` header. Local workaround: seed the resolver with configured RSA PEM material (`oidc.cppm:973-1010`) so key provenance matches, and build exact upstream claim payloads; the signature/header remain the shared stand-in.
- **SR-4 — `app::keystore::KeyStore`: expose enumeration (`list(purpose)`) and RSA `(n,e)` extraction.** The shared store only has `get`/`put`/`rotate`/`find_record` (`app/keystore/store.cppm:29-107`). Local workaround: enumerate `conf.oidc.key` from the config store and parse PEM/DER in-module (`oidc.cppm:238-324`, `:1012-1033`).
- **SR-5 — `app::store`: `find_active_user_by_user_id` and a user `is_verified` field** (`services/oidc_provider.rs:93-98`). Local workaround: `find_user_by_string` plus `status == "active"` as the verification proxy (`oidc.cppm:718-734`).
- **SR-6 — `app::services::ConfigStore` tenant/user base URLs.** Upstream reads `state.tenant.base_url` and `conf.user.base_url` (`services/oidc_provider.rs:25-31`, `utils/user.rs:404-410`). Local workaround: namespaces `tenant`/`user`, keys `base_url`, with the documented sandbox defaults (`oidc.cppm:959-972`).
