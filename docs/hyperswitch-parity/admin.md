- **Publishable key generation / UUIDv4 + env prefix** (`core/admin.rs:67-93`); C++ echoes no generated key (`admin.cppm:188-200`).
- **Merchant onboarding side effects**: AES-256 key generation, key-manager transfer, locker entity creation, key-store encryption (`core/admin.rs:326-360`); all absent.
- **Error mapping**: `GenericDuplicateError`, `GenericNotFoundError`, `MerchantAccountNotFound`, `InvalidRequestData` validation (`core/admin.rs:129-131`, `:152-154`, `:217-234` of `routes/admin.rs`, `:3382-3389`). C++ only emits `EMPTY_REQUEST`/`INVALID_JSON` (`admin.cppm:43-50`).
- **Org-to-platform state machine** with platform merchant creation (`core/admin.rs:220-320`). C++ sets two enum/string fields (`admin.cppm:144-150`).
- **Key-store/KV storage-scheme state machine** incl. `is_kv_soft_kill_mode` guard (`core/admin.rs:3391-3435`) and real bulk `total_updated` (`:3455-3472`). C++ hardcodes `kv_enabled=false` and `total_updated=0` (`admin.cppm:423`, `:854`).
- **Encryption key migration** via `transfer_encryption_key` (`core/admin.rs:4995-5006`); C++ returns parsed `limit` as `total_transferred` (`admin.cppm:462`).
- **Connector validation & crypto**: dummy-connector checks, connected-merchant/vault-connector rules (`core/admin.rs:2780-2801`), key-manager decryption during retrieve/update (`:3099-3112`). C++ echoes connector fields verbatim (`admin.cppm:283-297`).
- **Connector webhook management**: `register_connector_webhook` / `fetch_connector_webhook` outbound connector calls (`routes/admin.rs:1179-1185`, `:1230-1235`); C++ register just mirrors `WebhookDetailsRequest`, fetch returns empty response (`admin.cppm:500-513`, `:888-890`).
- **Route-level authorization**: `PlatformOrgAdminAuth`, `JWTAuthOrganizationFromRoute`, `JWTAuthMerchantFromRoute`, `JWTAuthMerchantFromHeader`, `ApiKeyAuthWithMerchantIdFromRouteAllowPlatform`, `JWTAndEmbeddedAuth`, granular `Permission` enums and `allow_connected`/`allow_platform` flags (`routes/admin.rs:25`, `:68-78`, `:133-143`, `:242-245`, `:314-329`, `:598-608`, `:687-698`, `:798-807`, `:837-846`, `:884-893`, `:962-971`). C++ uses one flat `ADMIN` check per handler.
- **Flow instrumentation / metrics / API lock actions / duplicate-request locking** (`routes/admin.rs:12`, `:18-27`, flow fields on every handler). Absent in C++.
- **v2 org-id-from-header** conversion (`routes/admin.rs:261-281`); C++ ignores headers beyond the token.
- **Real identifiers**: upstream ids come from DB/enums; C++ synthesizes ids from `body.size()` or the raw request path (`admin.cppm:61`, `:149-150`, `:549`, `:586`, `:623`, `:662`, `:700`, `:811-815`, `:852`, `:662`).

## Implementation disposition
- All DB persistence — IMPLEMENTED — repository CRUD used across handlers (`admin.cppm:57`, `:86`, `:146-168`, `:319-373`, `:733-753`, `:859-881`, `:1013`, `:1122`, `:1172-1177`, `:1348-1353`); local store substitutes upstream DB schema.
- Publishable key generation / UUIDv4 + env prefix — IMPLEMENTED — `uuid_simple()` + config env prefix + `pk_{env}_{uuid}` + `KeyedHasher` hash (`admin.cppm:333-343`).
- Merchant onboarding side effects — SUBSTITUTED — keymanager transfer / vault entity are external; local `key_store.put` AES-256 + AES-wrap locker secret and generated AES key used instead (`admin.cppm:344-353`).
- Error mapping — SUBSTITUTED — validation and error responses now mapped to local `AppErrorKind`s (`ALREADY_EXISTS`, `NOT_FOUND`, `INVALID_REQUEST`, `DUPLICATE_REQUEST`, `PRECONDITION_FAILED`, `CONNECTOR_ERROR`) not the exact upstream error enums (`admin.cppm:59-63`, `:146-150`, `:1907-1911`, `:1932-1973`).
- Org-to-platform state machine — IMPLEMENTED — config gate, preconditions, type flip, generated platform merchant id, merchant record persist, events (`admin.cppm:225-287`).
- Key-store/KV storage-scheme state machine — IMPLEMENTED — soft-kill guard, per-merchant scheme put, bulk loop with real `total_updated`, status read from config (`admin.cppm:739-753`, `:791-813`, `:1389-1393`).
- Encryption key migration — IMPLEMENTED — per-account new key, AES wrap, hash, `key_store.rotate`/`put`, `update_merchant_account`, counted `total_transferred` (`admin.cppm:852-882`).
- Connector validation & crypto — SUBSTITUTED — dummy/vault/killed validations implemented (`admin.cppm:1927-1975`); key-manager decryption replaced by `key_store`-backed AES key + `AesWrap` encrypt/decrypt (`:557-561`, `:666-675`, `:1213-1218`, `:1977-1984`).
- Connector webhook management — SUBSTITUTED — outbound connector webhook API is external; local `ConnectorWebhookRecord` persistence + encrypted secret + `webhook_delivery.enqueue` used instead (`admin.cppm:940-953`, `:963-992`, `:1428-1450`).

- Real identifiers — IMPLEMENTED — ids generated via `ids().uuid_v4()` (`org_`/`merchant_`/`mca_` prefixes) and retrieve responses sourced from repository records, not `body.size()`/raw path (`admin.cppm:71`, `:250`, `:317`, `:533`, `:1013-1021`, `:2034-2039`).
