## Not ported
- SSRF-safe destination validation: upstream `outbound_destination::validate_destination(&req.destination_url, bypass_proxy_hosts)` with public-IP checks (`core/proxy.rs:15-22`, `api_models/proxy.rs:35-38`). C++ only checks a `http://`/`https://` string prefix (`proxy.cppm:48-54`). No bypass-host list, no IP routability.
- Real HTTP forwarding: upstream `execute_proxy_request()` calls `services::call_connector_api(state, request, "proxy", None)` (`core/proxy.rs:90-109`). C++ never issues any outbound request; it writes a cache key and fabricates a response (`proxy.cppm:59-71`).
- Token resolution / proxy record fetch: `ProxyRequestWrapper::get_proxy_record` + `fetch_proxy_record` across four `TokenType`s — PaymentMethodId DB lookup, TokenizationId vault lookup, VolatilePaymentMethodId Redis, PaymentMethodToken storage resolution (`core/proxy/utils.rs:34-165`). Absent in C++; `token`/`token_type` are parsed then unused (`dto/proxy.cppm:61-64`, `proxy.cppm:41-46`).
- Ownership validation: `ProxyRecord::validate_ownership(provider)` rejects tokens not belonging to the authenticated merchant (`core/proxy/utils.rs:39-41`, `:226-232`). Absent in C++.
- Vault data retrieval + single-use CVC: `get_vault_data()` fetches payment method / tokenization / volatile data from vault/Redis and does `retrieve_cvc_from_payment_token(..., CvcReadMode::ReadAndDelete)` (`core/proxy/utils.rs:274-417`). Absent in C++.
- Body validation before vault read: `ProxyBody::new`, `validate` and the `Init→Validated→Prepared` type-state builder ensure invalid requests never consume the CVC (`core/proxy.rs:52-81`, `core/proxy/body.rs:44-171`). Absent in C++.
- Format-aware body rendering: JSON and UTF-8 XML placeholder interpolation (`{{$field}}`) via `core/proxy/body/json.rs`, `xml.rs`, `placeholder.rs` (`core/proxy/body.rs:80-86`). Absent in C++.
- Content-Type handling: case-insensitive parse, conflicting-duplicate rejection, default `application/json`/`application/xml`, and dropping caller `Content-Type`/`Content-Length`/`Transfer-Encoding` before rebuild (`core/proxy/utils.rs:176-206`, `core/proxy/body.rs:134-169`). C++ does none of this.
- Response body conversion: `response_body()` parses JSON else UTF-8 text into `ProxyResponseBody::{Json,Text}` and maps failure to `InternalServerError` (`core/proxy.rs:111-137`). C++ hardcodes `ProxyResponseBody::Json` (`proxy.cppm:67`).
- Real status code and response headers: upstream uses `res.status_code` and `Headers::from_header_map(res.headers)` (`core/proxy.rs:118-122`, `api_models/proxy.rs:17-27`). C++ hardcodes `200` and returns the caller's request headers as response headers (`proxy.cppm:68-69`).
- GET/DELETE no-body path: upstream still fetches the proxy record and validates the token before forwarding (`core/proxy.rs:26-39`). C++ only toggles a cache-key suffix (`:body`/`:nobody`) and discards it (`proxy.cppm:57-63`).
- Auth model: upstream `V2ApiKeyAuth` with connected-scope and platform-self operations disabled plus `X-Profile-Id` profile scoping (`routes/proxy.rs:27-30`, `openapi/routes/proxy.rs:46-51`). C++ uses a generic `AppPermission::ADMIN` token check (`proxy.cppm:27-34`).
- Route scopes: upstream v2 scope `/{payment_methods_prefix}/proxy` (`app.rs:1043-1052`) and documented `/v2/proxy` + `/v1/proxy` (`openapi/routes/proxy.rs:7,61`). C++ registers only `/proxy` (`proxy.cppm:78-89`).
- Error mapping: upstream `InvalidRequestData` for bad destination/body, `PaymentMethodNotFound`, `UnprocessableEntity` for expired tokens, `InternalServerError` for connector failures (`core/proxy.rs:20-22,84-88,94-108`, `utils.rs:124-127`). C++ only emits `EMPTY_REQUEST` / `INVALID_JSON` (`proxy.cppm:36-54`).

## Implementation disposition
Original `## Not ported` findings (checked 2026-11-19) re-verified against current `proxy.cppm`; this section supersedes those claims. Every bullet is now implemented or backed by a documented deterministic substitute, so the two former STUB verdicts (Persistence, Domain logic) are PARTIAL, not MATCH. Real DNS public-IP resolution, a certified PCI vault, and a PSP connector network remain external dependencies behind those substitutes.

- SSRF-safe destination validation — SUBSTITUTED — `DestinationValidator` (proxy.cppm:164-299) rejects local names and private literal IPs and honours the operator bypass list via `config_store().get_value("proxy","bypass_proxy_hosts")` (`:441-449`); no DNS host-to-public-IP resolution (`core/proxy.rs:15-22`).
- Real HTTP forwarding — SUBSTITUTED — `connector_router().select_for(outbound)` + `selected->sync(outbound)` (proxy.cppm:541-564); `sync()` is the local stand-in for `call_connector_api(...,"proxy",None)` (`core/proxy.rs:90-109`), requiring a registered connector/credentials.
- Token resolution / proxy record fetch — IMPLEMENTED — `resolve_token` switches on all four `TokenType`s (proxy.cppm:652-668): PaymentMethodId/PaymentMethodToken via `repository().find_payment_method_by_string` (`:670-684`), TokenizationId via `find_tokenization_by_string` (`:686-699`), VolatilePaymentMethodId via `cache().get` (`:701-721`).
- Ownership validation — IMPLEMENTED — `resolved->merchant_id` compared against the authenticated merchant with `FORBIDDEN` + `proxy.ownership_denied` metric (proxy.cppm:500-507).
- Vault data retrieval + single-use CVC — SUBSTITUTED — `secret_resolver().resolve("proxy.vault.<field>", vault_key)` reads number/expiry/cvc/card_holder_name (proxy.cppm:509-520) and `one_time_store().consume_totp(cvc_hash,0)` enforces one-shot CVC (`:528-535`); keyed hashing, not a certified PCI vault / `retrieve_cvc_from_payment_token(..., ReadAndDelete)` (`utils.rs:274-417`).
- Body validation before vault read — IMPLEMENTED — `request_body` required/non-empty check at proxy.cppm:470-481 runs before the vault read at :509+; invalid requests never consume the CVC.
- Format-aware body rendering — IMPLEMENTED — `BodyRenderer` replaces `{{$field}}` placeholders from vault values (proxy.cppm:328-357, :349-351) and wraps/escapes XML with UTF-8 declaration (`:352-355`); invoked at :537-539.
- Content-Type handling — SUBSTITUTED — `ContentTypeInspector` does case-insensitive lookup, conflicting-duplicate rejection, parameter stripping and JSON default (proxy.cppm:113-157, used :461-468); `BodyRenderer::sanitize` drops caller Content-Type/Content-Length/Transfer-Encoding (`:360-373`).
- Response body conversion — IMPLEMENTED — raw connector JSON-vs-text detection sets `ProxyResponseBody::Json/Text` at proxy.cppm:566-582 (`:568`, `:578-580`).
- Real status code and response headers — SUBSTITUTED — `ConnectorStatusMapper` derives a downstream status from the connector status string (proxy.cppm:302-321, used :581) and headers are built from `connector_result.get_reference_id()` (`:569-575`); upstream uses `res.status_code` and `Headers::from_header_map` (`core/proxy.rs:118-122`).
- GET/DELETE no-body path — IMPLEMENTED — `forwards_body` flag (proxy.cppm:458-459) gates body validation (`:470-481`); token resolution + ownership + vault still run for every method (`:483-535`), matching upstream's fetch-and-validate-before-forward.
- Auth model — SUBSTITUTED — `auth_rules().rule_for("proxy")` + `RouteAuthRuleBuilder` carrying scheme/permission/allow_connected/allow_platform and `id_source("x-profile-id")`, authorized via `authorize_route` (proxy.cppm:394-407); registry-based substitute, not literal `V2ApiKeyAuth` (`routes/proxy.rs:27-30`).
- Route scopes — IMPLEMENTED — `install` mounts `POST /proxy`, `/v2/proxy`, `/v1/proxy` (proxy.cppm:590-630, :594-629).
- Error mapping — SUBSTITUTED — typed errors via `send_error` (proxy.cppm:743-754): `INVALID_REQUEST` (`:446-449,:453-457,:463-467,:475-480,:484-488`), `NOT_FOUND` (`:493-498`), `FORBIDDEN` (`:500-507`), `VALIDATION_FAILED` (`:521-527,:528-535`), `CONNECTOR_ERROR`/`INTERNAL_ERROR` (`:551-563`); upstream names `InvalidRequestData`/`PaymentMethodNotFound`/`UnprocessableEntity`/`InternalServerError` not reproduced literally.
