## Not ported
- Superposition SDK dispatch and output conversion for every flow: `handle_superposition_proxy_flow` calls `send_with(...superposition_sdk_client())` and converts with `list_*_to_response` / `*_output_to_struct` (`core/superposition_proxy.rs:346-355`, `399-410`, `440-451`, `480-491`, `522-533`, `564-575`, `615-625`, `664-683`, `726-737`, `787-798`). C++ handlers synthesize `PaginatedListResponse` with `set_data({})`, echo `page`/`count`, or echo path key only (`cppm:70-75`, `103-108`, `135-140`, `170-173`, `203-206`, `270-287`, `332-334`, `387-390`, `428-433`).
- SDK error mapping `map_superposition_err` (BadRequest, NotFound, default InternalServerError with printable context) (`core/superposition_proxy.rs:135-155`). C++ maps only local validation errors via `AppErrorBuilder` (`cppm:760-771`).
- `extract_proxy_headers` compares `x-org-id`/`x-workspace` to `configured_org_id()`/`configured_workspace_id()` and forbids mismatch (`core/superposition_proxy.rs:157-180`). C++ `require_proxy_scope` checks only header presence (`cppm:564-584`); configured values never consulted.
- Full typed `ListContextsQuery` fields: `sort_on`, `sort_by`, `plaintext`, `dimension_match_strategy`, `prefix`, `created_by`, `last_modified_by` (`core/superposition_proxy.rs:194-245`). C++ reads `count`/`page` and discards the rest (`cppm:57-66`).
- Full typed `ListAuditLogsQuery` fields: `all`, lenient `parse_datetime` for `from_date`/`to_date`, comma-split `table`/`action`, `username`, `sort_by` (`core/superposition_proxy.rs:264-315`). C++ reads `count`/`page`, discards the rest (`cppm:416-424`).
- `ListDefaultConfigsQuery.name` parsed and sent to SDK (`core/superposition_proxy.rs:255-262`, `424-430`). C++ discards `name` (`cppm:99`).
- `ContextPutRequest` conversion via `context_put_from_request`, with `doc_map_to_json` used for scoped validation (`core/superposition_proxy.rs:589-613`). C++ uses generic `decode_generic` over the whole body (`cppm:231-249`).
- Server-owned context id from SDK output (`core/superposition_proxy.rs:625`). C++ generates a local `ctx_` payment id (`cppm:271`).
- Resolved-config deserialization via `document_to_value` / `serde_json::from_value` and error mapping (`core/superposition_proxy.rs:675-681`). No equivalent in `handle_resolve_detailed_config` (`cppm:332-334`).
- `ApiEventMetric` on response types and `ApplicationResponse::Json` wrapping / `server_wrap` flow instrumentation (`core/superposition_proxy.rs:325`, `344-355`; `routes/superposition_proxy.rs:18`, `32-59`). C++ uses `metrics().record_flow` + counter only (`cppm:754-758`).
- JWT permission is the dedicated `ProfileSuperpositionConfigRead/Write` (`routes/superposition_proxy.rs:52-56`, `272-276`). C++ uses generic `PROFILE_READ`/`PROFILE_WRITE` (`cppm:38`, `216`); auth scheme/allow flags reconstructed in `authorize_request` (`cppm:549-562`).
- `ScopingDimension::from_dimension_param` accepts only keys matching `dimension[...]` with strict suffix and known inner names (`core/superposition_proxy.rs:57-61`). C++ `scoped_name` strips `dimension[`/`]` without validating the inner name against the known set (`cppm:734-740`).
