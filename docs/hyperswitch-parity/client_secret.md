## Not ported
- `ResourceId::Customer(GlobalCustomerId)` is a typed newtype carrying the customer id (`api_models/client_secret.rs:9-12`); C++ `ResourceId` is a valueless enum (`dto/client_secret.cppm:28-31`) and the handler parses the id out of raw text (`client_secret.cppm:51`, `:211-231`). Lossy, not schema-driven input.
- Customer existence check uses `db.find_customer_by_global_id(global_customer_id, platform key_store, storage_scheme)` with `CustomerNotFound` mapping (`helpers.rs:4702-4711`); C++ scans local `repository().list_customers()` comparing `get_customer_id()` (`client_secret.cppm:58-70`). Global-id resolution and platform-scoped key store lookup absent.
- Secret generation uses `Secret::new(generate_time_ordered_id("cs"))`, a time-ordered id (`helpers.rs:4744`); C++ derives the secret from a keyed hash of `id:merchant_id` + Base64Url (`client_secret.cppm:74`, `:233-240`). Different algorithm/format; upstream id is `ClientSecretId::generate()` (`helpers.rs:4743`) vs C++ `ids().payment_id("cs_")` (`:72`).
- Validity window comes from configured `state.conf.eph_key.validity` (`helpers.rs:4753`); C++ hardcodes 24 hours (`client_secret.cppm:88`, `:98`, `:257-260`).
- Create writes a single serialized `ClientSecretType` to both the id key and secret key in Redis hash `"csh"` using HSETNX (duplicate → `StorageError::DuplicateValue`) and sets expire-at to `expires` unix timestamp (`db/client_secret.rs:54-100`); C++ stores the full JSON response under the id key and the raw secret under the secret key in a generic cache, with no HSETNX collision handling (`client_secret.cppm:97-100`, `:262-270`).
- `get_client_secret` prefixed-key lookup `"cs_{key}"` from hash `"csh"` (`db/client_secret.rs:108-118`) has no direct equivalent; C++ delete reads only the id-key record (`:126`).
- Upstream datetime fields are typed `time::PrimitiveDateTime` (`api_models/client_secret.rs:33-35`); C++ `PrimitiveDateTimeValue` wraps unix-second strings (`dto/client_secret.cppm:20-26`, handlers `:242-255`), so wire format differs.
- Upstream error mapping: `CustomerNotFound` (`helpers.rs:4710`), `GenericNotFoundError{"Client secret not found"}` (`helpers.rs:4771-4773`), and `InternalServerError` change-contexts (`:4726`, `:4755`, `:4775`); C++ emits flat `NOT_FOUND`/`INVALID_JSON`/`EMPTY_REQUEST` app errors (`client_secret.cppm:44`, `:53`, `:67`, `:128`, `:136`).
- Route auth flags `allow_connected_scope_operation`/`allow_platform_self_operation` and `LockAction::NotApplicable` (`routes/client_secret.rs:32-36`, `:56-60`) have no C++ equivalent; handlers use a single `AppPermission::PAYMENT_WRITE` check (`client_secret.cppm:36`, `:114`, `:182-194`).
- C++ adds flow/counter metrics (`record_flow`, `client_secret_create`/`client_secret_delete` counters, `:102-103`, `:145-146`) not present in the upstream create/delete helpers.
- POST registered at `"/"` under `/v2/client-secret` (`client_secret.cppm:157-158`) vs upstream resource `""` (`app.rs:2311`); trailing-slash behavior may differ depending on router config.

## Implementation disposition

Two items (typed `ResourceId` newtype, typed `PrimitiveDateTime`) remain PARTIAL pending shared DTO follow-up (`dto/client_secret.cppm:20-31`); every other divergence is a documented deterministic local substitute.

- Typed `ResourceId::Customer(GlobalCustomerId)` newtype — SUBSTITUTED — DTO enum still valueless (`dto/client_secret.cppm:28-31`); handler deserializes DTO (`:51`) and extracts `resource_id.Customer` from decoded JSON tree (`:55`, `:219-246`). Typed newtype needs shared DTO follow-up.

- Configured `eph_key.validity` window — IMPLEMENTED — `eph_validity_hours()` reads `config_store().get_value("eph_key", "validity")` with 24h fallback (`:75`, `:281-296`); drives response `expires` (`:98`) and cache TTL (`:108`).
