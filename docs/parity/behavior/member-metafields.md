### GET `/members/metafields/:namespace` — MATCH (group 42 strict parity)

**Ghost**

2. Operation: exported key `browse`, `docName: 'members_metafields'` (`member-metafields.ts:47,49`).
3. Input: `options: ['namespace','filter']`, validation `namespace` required; `filter` optional NQL (`member-metafields.ts:51-52`). `namespace` is validated by `namespaceRoute` → `NamespaceSchema` (`serializers.ts:8-16`). `filter` is parsed as NQL to a Mongo query; malformed filters raise 400 `BadRequestError` (`definitions-service.ts:815-827`). No body, multipart or headers read.
4. Auth/permissions: admin auth on the mount (`admin/routes.js:200`); `permissions:false` on the op (`member-metafields.ts:53`); no permission service call because definitions only say the site collects a field (`member-metafields.ts:27-32`).
5. Status/headers: default 200; `headers: noCacheInvalidation` = `{cacheInvalidate:false}` (`member-metafields.ts:44,50`). The framework emits an `X-Cache-Invalidate` header only when `apiConfigHeaders.cacheInvalidate` is truthy, so `false` emits none (`packages/api-framework/src/headers.ts:135-144`).
6. Call chain: `query(frame)` → `booted().definitions.browse({...namespaceRoute(frame.options), filter: frame.options.filter}, ADMIN)` (`member-metafields.ts:54-59`). Service parses filter, chooses `ANY_STATUS` when a filter references `status` (including inside `$and/$or/$nor`) else `ACTIVE_ONLY`, calls `fields.definitions(executor,{audience,status,namespace,filter}).read`, selects `*`, and maps rows through `readStoredField`/`metafieldCodec` in `inFieldOrder` (`definitions-service.ts:168-199,832-849`). Audience `ADMIN` reads every member-access level (`access.ts:24-28`). No events, jobs, mail, webhooks or third-party calls on reads.
7. Cache: no server cache; `cacheInvalidate:false` only (`member-metafields.ts:44,50`).
8. Output: serializer `browse: serializeMany` in `utils/serializers/output/member-metafields.ts:12-14,23` → `toMetafieldsResponse` builds `{members_metafields: [...]}` with snake_case keys and ISO `created_at`/`updated_at` (null when absent), strips `createdAt`/`updatedAt` (`services/members-metafields/serializers.ts:23-34`). Empty namespace yields `{"members_metafields":[]}`, not 404 (`admin/routes.js:203-205`).

## Module-level notes

- **Shared C++ storage**: all seven admin metafields operations live in `MembersOperations` (`include/blog/handlers/membership/members/operations.cppm:30-33`) using a single `core::cache::Cache& m_cache` (`:775`). Metafields use prefix `kMeta = "members:metafields:"` (`:492`) with `Ttl{}.never()` and tag `{"members"}` (`:352,608-623`). `load_metafields`/`store_metafields` serialize a `MetaField` struct (`:519-531,574-624`) that adds a C++-only `bound` flag and hard-coded ISO fallback timestamps. The members-side trio does **not** use this cache — it reads `ctx.store().json_for("members_metafields")` (`member_metafields_members/.../execute.cppm:27`), so the two C++ audiences can disagree about the same field list.
- **Cross-route side effects in C++**: create/reorder/edit/destroy rewrite the whole cached list; destroy also erases cached `values:` keys (`operations.cppm:365,431,484,448-453`). No route sets `bound` true, so the stored flag stays `false` and cannot drive the Ghost conditional invalidation.
- **Headers**: the Ghost controller suppresses cache invalidation on every route (`member-metafields.ts:44,50,63,76,87,103,119,144`; `member-metafields-members.ts:31`) and the framework emits no header for `false` (`headers.ts:135-144`). None of the seven admin C++ handlers write headers; the members-side C++ handler writes `X-Cache-Invalidate: false` (`metafields_browse/handler.cppm:28`) — a divergence, not parity.
- **Auth model**: all admin C++ handlers replace `mw.authAdminApi` with an inline non-empty token check (`members_metafields_*/handler.cppm:35-39`); the members C++ handler replaces `loadMemberIdentity` + `rejectWhenAnonymous` with an `X-Member-Id` header (`metafields_browse/.../execute.cppm:14-18`).
