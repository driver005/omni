- Billing-processor / connector integration: no `BillingHandler::create`, no `pause/resume/cancel_subscription_on_connector`, no `create_subscription_on_connector`, no `get_subscription_estimate` (`core.rs:45-51,75-77,143-153,196-202,352-358,511-522,561-572,612-623,679-685`). - Invoice/payment lifecycle: create payment (confirm=false), create/update invoice, latest-invoice lookup, confirm/update payment, invoice-sync jobs (`core.rs:80-114,217-283,335-350,411-422,661-718`). Absent in C++.
- Connector-side customer creation and connector customer-id backfill (`core.rs:42-44,192-194,219-240,359-390`). Absent in C++.
- Real estimate calculation: upstream returns connector total/currency + line items (`core.rs:469-495`); C++ returns `0`/USD and a single synthetic line item (`subscription.cppm:477-493`).
- Real subscription items/prices: upstream calls billing `get_subscription_items` + `get_subscription_item_prices` with `item_type` filter (`core.rs:125-174`); C++ builds one fabricated item from a local record (`subscription.cppm:347-364`).
- Client-secret auth validation: upstream `find_and_validate_subscription` on confirm/estimate/items (`core.rs:137-141,328-332,479-483`); C++ only hash-filters items (`subscription.cppm:330-339`) and never validates confirm/estimate.
- Upstream auth model: `HeaderAuth(ApiKeyAuth)`, `JWTAuth` with `ProfileSubscriptionRead/Write`, SDK/client-secret auth (`check_sdk_auth_and_get_auth` / `check_client_secret_and_get_auth`), `allow_connected`/`allow_platform` flags (`routes/subscription.rs:74-85,118-121,154-157,190-193,214-235,255-263,283-303,321-329,362-373,403-413,432-443,488-491,523-533`). - Connector-derived status/state machine: upstream uses `SubscriptionStatus::from(connector_response.status)` and connector-returned `paused_at`/`next_billing_at`/`cancelled_at` (`core.rs:523,574,625,529-540,580-591,631-642`); C++ writes literal strings and reuses `updated_at`.
- Request validation: upstream `request.validate()` on create-and-confirm/confirm (`core.rs:182-186,316-321`); C++ only checks non-empty body + JSON parse.
- Upstream gating: routes are `#[cfg(all(feature = "oltp", feature = "v1"))]` with `LockAction::NotApplicable` (`app.rs:1482`; `routes/subscription.rs:86,122,158,194,264,330,374,415,456,492,535`); no C++ equivalent (no feature gate, no locking concept needed).

Profile is auth-claim sourced, not a parsed `X_PROFILE_ID` claim.
- Billing-processor / connector integration — SUBSTITUTED — `call_connector` selects a merchant connector and dispatches link/verify/authorize/cancel/sync (`subscription.cppm:1094-1116`); invoked in create, items, estimate, confirm, update, pause/resume/cancel (`:137,360,448,615,695`). Generic connector substitute; no real billing-processor API.
- Invoice/payment lifecycle — SUBSTITUTED — `setup_billing` creates a `PaymentIntentRecord` via `repository().save_payment` (`:1226-1238`) plus invoice state in `config_store` (`:1160-1201`); confirm updates payment to succeeded (`:362-367`) and schedules `invoice_sync` via `process_trackers` + `events` (`:375-378,1242-1247`). DB invoice tables replaced by config_store.
- Connector-side customer creation and connector customer-id backfill — SUBSTITUTED — `setup_billing` calls `billing_customer_create` and stores returned id in `config_store` (`subscription.cppm:1215-1219`), dispatched via connector `create_link` (`:1103-1105`).
- Real estimate calculation — SUBSTITUTED — `price_for` reads `config_store().get_value("subscription_prices", key)` with deterministic hash fallback (`subscription.cppm:1051-1078`); response uses that amount/currency with line items (`:608-640`) and calls connector `get_subscription_estimate` (`:615`). Config-derived, not connector-authoritative.
- Real subscription items/prices — SUBSTITUTED — handler builds priced items from local records with `item_type=addon` filter and `price_for` (`subscription.cppm:418-469`), calls connector `get_subscription_items` (`:448-450`). Still one record-derived item, not upstream multi-item fetch.
- Client-secret auth validation — IMPLEMENTED — confirm via `client_secret_matches` (`subscription.cppm:330-351,986-996`); estimate via `find_subscription_by_client_secret` (`:597-606,998-1015`); items hash-filter with FORBIDDEN on miss (`:420-438`); secrets minted with `KeyedHasher` (`:976-984`).
- Upstream auth model — SUBSTITUTED — per-op `auth_rules().rule_for(...)` + `authorize_route` in every handler (`subscription.cppm:36-37,100-101,168-170,237-239,307-309,405-407,519-521,582-584,656-658,727-729`), profile resolution (`:925-936`) and client-secret checks (above).
