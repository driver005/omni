# Design system comparison: Ghost/Shade vs Medusa UI

Research scope: read-only. Sources: `/home/default/cc/omni/docs/Ghost` (Ghost, source of truth) and
`/home/default/cc/omni/medusa-repo` (Medusa). Paths below are relative to `/home/default/cc/omni`.
`visual/` is a verbatim copy of Ghost's frontend: `diff -rq docs/Ghost/apps/shade visual/apps/shade`
reports only `node_modules` as different; `tokens.css` and `theme-variables.css` are byte-identical.

## Executive summary

Both systems are React + Tailwind v4 CSS-variable systems built on Radix primitives, semantic tokens, `cva` variants, and `clsx`/`tailwind-merge`, but they diverged on token authoring: Shade hand-maintains purpose-named semantic tokens in two CSS files with an admin7 A/B palette flag, while Medusa generates all tokens from Figma into a dual Tailwind v3/v4 preset with `ui-` prefixed utilities. Shade is a tightly scoped internal design system with 62 UI components, layered primitives/patterns/page templates, and strict "no raw color / no `dark:` for color" rules; Medusa is a published 3-package system (`@medusajs/ui` 4.2.14, `@medusajs/ui-preset` 2.22.7, `@medusajs/icons` 2.22.7) designed for third-party admin extensions and storefronts. For `visual/`, Shade can be kept as-is; the real conflict is Ghost's fetch-based data layer (`admin-x-framework`) versus the Rust SDK/WASM seam in `packages/congelado-sdk`, not the design system itself.

## Practical implications for `visual/`

**Reuse directly**

- The whole of `visual/apps/shade` is identical to the Ghost source (only `node_modules` differs). Keep Shade as the DS; consume layer subpaths, never the root barrel (`apps/shade/AGENTS.md`, `CONTRIBUTING.md:268-281`).
- Token discipline is portable and cheap: semantic-first, no hex/raw utilities, no color `dark:` variants (`tokens.mdx:63-104`). This works unchanged with the Rust SDK because tokens are presentation-only.
- Radix-based accessible primitives, `cva` + `cn` API shape, `data-slot` contracts, and the four-state component checklist are independent of the data layer (`component-contracts.mdx:11-19`, `ui/button.tsx:11-83`).
- Dark-mode mechanics are reusable: `.dark` on `<html>`, `theme-switching` class for single-paint flip (`admin-x-framework/src/utils/admin-theme.ts:13-30`), and `ShadeProvider darkMode` for portals (`README.md:68`).
- Selectively borrow Medusa's ideas: one generated `theme.css` from a token source (`ui-preset/src/theme-css.ts:56-138`), a `ui-`-style prefix if two token sets must coexist, and a v3/v4 compatibility test if storefront surfaces need Tailwind 3 (`ui/AGENTS.md` Gotchas). Do **not** copy Medusa's token names or Figma pipeline wholesale.

**Conflicts with the Rust SDK plan**

- `visual/` is a verbatim Ghost frontend, so its request logic is Ghost's, not ours: `visual/apps/admin-x-framework/src/utils/api/fetch-api.ts:1-...` owns method/body/headers, session expiry redirects, retries, timeouts, uploads, Sentry, and probes `/ghost/api/` paths (`fetch-api.ts:60-64`). `visual/README.md:7` and `sdk/README.md:1-5` say requests must go through `packages/congelado-sdk/src/index.ts` → WASM. Keeping Ghost's fetch layer and adding the SDK yields two request stacks with divergent auth/error semantics.
- The SDK wrapper is currently tiny: `CongeladoSdk.create(baseUrl)`, `.baseUrl`, `.listPosts()` returning `{status}` (`visual/packages/congelado-sdk/src/index.ts:14-45`). It is async-initialized, whereas Ghost's framework hooks/providers are synchronous; call sites need an async boundary. It has no session/token/refresh surface yet (Rust `auth/auth.rs` exists but isn't in the wrapper).
- Theme preference ownership differs: Ghost persists `nightShift` server-side via user preferences (`apps/admin/src/hooks/use-theme.ts:22-60`), Medusa uses localStorage (`theme-provider.tsx:4-36`), and the Rust API is generated from C++ OpenAPI (`sdk/README.md:7-15`). The chosen persistence mechanism must be an explicit SDK/API decision, not inherited from Ghost.
- Medusa's `ui-*` utilities and Shade's semantic utilities encode different token vocabularies; mixing both design systems in one `visual/` surface would create two sources of truth for the same visual concepts.

**Prioritized recommendations**

1. **Define the data-layer seam before UI work.** Replace `admin-x-framework` request construction with `congelado-sdk` calls; expand the WASM surface to cover session/auth, list/detail, and mutations, with an explicit async-init boundary. Never leave Ghost's `/ghost/api/` fetch path active in `visual/` (`visual/README.md:7`, `congelado-sdk/src/index.ts:1-45`, `fetch-api.ts:60-64`).
2. **Pin Shade as the single DS and set a sync rule with upstream.** `visual/apps/shade` is a byte-identical copy; decide whether to vendor it or track `docs/Ghost/apps/shade` via a documented patch/sync process, and keep token edits in `theme-variables.css`/`tailwind.theme.css` only (`CONTRIBUTING.md:262-266`).
3. **Lock the theming contract now.** Keep semantic tokens + `.dark` on `<html>` + `theme-switching`; drop `admin7Design` (marked temporary, `theme-variables.css:203-205`) unless the A/B palette is wanted; choose one persistence source (Rust API vs localStorage) and avoid `dark:` color variants (`tokens.mdx:92-104`).
4. **Add accessibility/i18n gates to the new frontend.** Enforce Shade's four-state + semantic-token checklist (`component-contracts.mdx:11-19`) and Ghost's one-sentence-per-`t()` rule (`internationalization.md:20-45`); add `prefers-reduced-motion` coverage for any new motion, since neither design system has a global rule for it beyond Shade's large-title case (`styles.css:260-264,316-325`).
5. **Only adopt Medusa's dual-preset strategy if a Tailwind 3 consumer exists.** Otherwise stay CSS-first v4 like Shade (`apps/shade/README.md:12-49`). If needed, mirror the separation of generated token CSS from the component package (`ui-preset/src/theme-css.ts:56-138`) rather than copying Medusa's Figma/FIGMA_TOKEN workflow.
