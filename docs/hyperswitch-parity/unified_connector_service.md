## Not ported
- Redis as the kill-switch backing store: upstream uses `get_redis_conn` + hash fields, `HINCRBY`/`EXPIRE` with `UCS_KILL_SWITCH_TTL_IN_SECONDS` (`core/unified_connector_service/kill_switch.rs:173-196,435-521`). C++ uses ephemeral cache with no TTL — counters reset on restart (`unified_connector_service.cppm:114-117,200-202`).
- Tenant vs global store split: upstream routes primary scopes through `state.store` and the shared shadow counter through `state.global_store` (`kill_switch.rs:545-552,584-588,915-924`). C++ has one cache, no tenant isolation (`unified_connector_service.cppm:114-117,200`).
- Shadow threshold resolution: upstream reads Superposition `UCS_SHADOW_KILL_SWITCH_THRESHOLD` with fallback to `comparison_service.shadow_kill_switch_threshold` (`kill_switch.rs:928-965`); C++ hardcodes `1` (`unified_connector_service.cppm:125-130`).
- Full redis-key scope extraction: upstream `rollout_scope_in` uses `split_once(prefix)` so a key with any leading tenant prefix is accepted (`kill_switch.rs:52-63`); C++ only strips when the key *starts with* `ucs_kill_switch_` (`unified_connector_service.cppm:61-64,191-194`).
- `RolloutConfig` typed parse via serde with `UCS_ROLLOUT_CONFIG_NOT_CONFIGURED` sentinel filtering (`kill_switch.rs:613-638`); C++ decodes a generic JSON tree and reads integer fields heuristically (`unified_connector_service.cppm:71-103`).
- Response-content parity on reset: upstream returns `StatusOk` with no JSON body (`kill_switch.rs:568`); C++ returns a synthetic `cleared:true` body (`unified_connector_service.cppm:214-218`).
- Instrumentation payload: upstream uses named `Flow` + `ApiEventMetric` on `KillSwitchStatusResponse` and Redis-error fail-closed logging (`kill_switch.rs:105-169,540,580-600`); C++ uses `metrics().record_flow`/counter strings with no fail-closed semantics (`unified_connector_service.cppm:139-140,211-212`).
- The entire non-route core module is unported: gRPC payment-method conversion `ForeignTryFrom<PaymentMethod>` (`core/unified_connector_service.rs:111-718`), access-token caching (`get_access_token_from_ucs_response`/`set_access_token_for_ucs`, `:774-862`), UCS availability checks (`check_ucs_availability` variants, `:894-962`), integration-type determination + inline UCS-only connector list (`determine_connector_integration_type`, `INLINE_UCS_ONLY_CONNECTORS`, `:964-1032`), and rollout execution routing (`should_call_unified_connector_service` + db/superposition variants, `:1035-1178+`). No C++ equivalents exist; the C++ module is restricted to the two kill-switch endpoints.
- Kill-switch *enforcement* path is absent: upstream `is_kill_switched`, `record_decline`, `check_record_failure`, increment/TTL refresh, and shadow `check_record_failure`/`should_stop` (`kill_switch.rs:106-169,274-303,435-521,1027-1116`) are payment-flow hooks with no C++ counterpart — only the read/reset API surface is mirrored.
- Feature gate `#[cfg(feature = "olap")]` on the whole UCS scope (`app.rs:2444`). No equivalent gating in C++.

## Implementation disposition

- Redis as the kill-switch backing store — DEFERRED — Redis `get_redis_conn`/`HINCRBY`/`EXPIRE` TTL is external infrastructure; handler still uses ephemeral `cache()` with no TTL (`unified_connector_service.cppm:53,119,121,315-318`).
- Tenant vs global store split — SUBSTITUTED — one cache partitioned by key namespace: `global/ucs_shadow_killed` vs `tenant/ucs_kill_switch_<scope>` (`unified_connector_service.cppm:297-313`); no real two-store isolation.
- Shadow threshold resolution — SUBSTITUTED — `shadow_threshold()` reads repository config → `superposition().get_config` → comparison key → fallback 1 (`unified_connector_service.cppm:364-388`); local services substitute for real Superposition/comparison-service.
- Full redis-key scope extraction — IMPLEMENTED — `resolve_scope()` uses `find(counter_prefix)` + erase-through (`split_once` semantics), accepting any leading tenant prefix (`unified_connector_service.cppm:287-292`).
- `RolloutConfig` typed parse via serde with sentinel filtering — IMPLEMENTED — `load_rollout_config()` filters `"not_configured"` and uses `serde::Ser::deserialize<RolloutConfigView>` with reflection (`unified_connector_service.cppm:324-342,425-447`), backed by local `repository().get_config`.
- Response-content parity on reset — IMPLEMENTED — `send_json(res, send, std::string_view{}, true)` returns an empty body matching upstream `StatusOk` (`unified_connector_service.cppm:134-135`).
- Instrumentation payload — SUBSTITUTED — `metrics().record_flow(...)` + named counters with a fail-closed parse-error counter (`unified_connector_service.cppm:77-78,131-132,336-338`); no typed `ApiEventMetric`/`Flow` enum.
- Entire non-route core module unported — DEFERRED — gRPC payment-method conversion, access-token caching, UCS availability and rollout routing need external UCS/gRPC connector services; handler installs only the two kill-switch routes (`unified_connector_service.cppm:138-165`).
- Kill-switch enforcement path absent — DEFERRED — `is_kill_switched`/`record_decline`/TTL refresh are payment-flow hooks outside this read/reset API; comment records TTLs owned by enforcement hooks (`unified_connector_service.cppm:299-302`).
- Feature gate `olap` — DEFERRED — no C++ cfg-feature equivalent; routes installed unconditionally (`unified_connector_service.cppm:138-165`).
