## Shared contract requests
- `include/app/auth/registry.cppm` (outside this module, unedited): `customers_create`, `customers_retrieve*`, `customers_list*`, `customers_update`, `customers_delete` entries use generic `API_KEY`/`JWT` + `USER_*` schemes, and `get_customer_mandates` uses `USER_READ` rather than `MANDATE_READ`; `migrate_global_id` uses `JWT`+`MERCHANT_READ` rather than `PLATFORM_ADMIN`+`ADMIN`. No change is required for this module to be MATCH; if the registry is aligned, the handler can switch back to `rule_for(...)` with no wire change.
- `include/app/store/customers.cppm` / `include/app/db/schema.cppm` (outside this module, unedited): `CustomerRecord` has no address/tax/document/global-id/status columns. The handler persists these in local reflected tables `customer_extensions` and `customer_addresses` registered in `install()` (`customers.cppm:418-425`). If the shared store gains those columns, the local extension tables can be retired with no wire change.
- `include/app/keystore` / a certified key manager (outside this module): `encrypt_pii` uses `AesWrap` + `key_store().get("customer_pii","v1")` with a fixed local fallback (`customers.cppm:1421-1426`). A real AES-GCM/vault key manager can replace it without changing the response shapes.
- No changes to `all.cppm`, `routes.cppm`, `base.cppm`, `context/`, `services/`, `auth/`, `store/`, or `docs/hyperswitch/` were made or are required.
