## Not ported
- `server_wrap` middleware semantics: per-op `Flow` instrumentation (`CreateConfigKey`, `ConfigKeyFetch`, `ConfigKeyUpdate`, `ConfigKeyDelete`), request handling, and `LockAction::NotApplicable` (`routes/configs.rs:16,22,25-33,36,42,45-53,56,63,68-76,80,86,89-97`). C++ records only local flow names + counters (`configs.cppm:64-65,95-96,133-134,168-169`); no lock/instrumentation layer.
- Distinct retrieve auth: upstream wraps `ADMIN_API_AUTH` in `InternalApiKeyAuth` for GET only (`routes/configs.rs:51`). C++ applies the identical `AppPermission::ADMIN` rule to all four ops (`configs.cppm:34,76,107,145`).
- Typed request/response DTOs: upstream `Config{key,value}` and `ConfigUpdate{key(skip_deserializing),value}` with serde validation (`types/api/configs.rs:2-12`). C++ uses `Ser::decode_generic` + `field_string("key")` and never validates/preserves a typed `value` field (`configs.cppm:44-55,117-124,320-329`).
- Persistent DB storage + canonical error mapping: upstream `insert_config`/`find_config_by_key_optional`/`update_config_by_key`/`delete_config_by_key` with `DuplicateConfig` and `ConfigNotFound` (`core/configs.rs:24-31,38-42,51-54,60-63`). C++ substitutes a process-local cache (`configs.cppm:331-358`), so state is not durable or shared across instances; errors use `ALREADY_EXISTS`/`NOT_FOUND` instead (`configs.cppm:57,85,126,153`).
- Extra C++ error paths with no upstream equivalent on these routes: `EMPTY_REQUEST` and `INVALID_JSON` (`configs.cppm:41,46,114,119,90,163`); upstream deserialisation errors surface as `server_wrap` failures, not these kinds.
- Compile-time v1/v2 feature gating: upstream compiles exactly one scope under `#[cfg(feature = "v1")]`/`#[cfg(feature = "v2")]` with `AdminApiAuth` vs `V2AdminApiAuth` (`routes/configs.rs:11-14`, `app.rs:2412,2427`). C++ registers both scopes unconditionally and uses one auth scheme for both (`configs.cppm:178-270`); the `is_v2` helper only affects path parsing (`configs.cppm:287-297`).
- Broader config subsystem in `core/configs.rs` not exposed by these four CRUD routes and absent from C++: `ConfigType` parsing (`core/configs.rs:67-155`), `DatabaseBackedConfig`, and Superposition/dimension-aware resolution with DB fallback (`core/configs.rs:157-399`). These are internal library helpers, not route behaviors, so they are out of scope for direct route parity but represent a large unported surface.

## Implementation disposition
Re-verified 2026-11-20 against `include/app/handlers/configs.cppm`. Every `## Not ported` bullet resolved:

- `server_wrap` middleware semantics — SUBSTITUTED — handler records per-op flow names + counters via `m_context->metrics()` (`configs.cppm:75-76,108-109,156-157,192-193`); no `server_wrap` Flow instrumentation and no lock layer, but upstream declares `LockAction::NotApplicable` so no lock is required (`routes/configs.rs:25-33`). Local metrics stand in for upstream flow telemetry.
- Distinct retrieve auth — IMPLEMENTED — registry assigns `AuthScheme::API_KEY` to `config_key_retrieve` and `PLATFORM_ADMIN` to the other three (`app/auth/registry.cppm:59-62`); handler applies the per-op rule via `authorize_operation` (`configs.cppm:34,88,120,168,302-304`). Old flat `AppPermission::ADMIN` check removed.
- Typed request/response DTOs — SUBSTITUTED — arbitrary-JSON `value` preserved as raw `serde::Value` via `field_value` (`configs.cppm:343-357`), stored in typed `ConfigRecord` (`configs.cppm:62-64`; `app/store/ops_records.cppm:381-424`), and emitted as canonical `{key,value}` (`configs.cppm:361-367`). Input is still generic `decode_generic` + manual presence checks, not a compile-time serde DTO (`configs.cppm:44-58,128-142`).
- Persistent DB storage + canonical error mapping — IMPLEMENTED — DB-backed repository `create_config`/`find_config_by_key`/`update_config`/`remove_config` (`configs.cppm:65,96,149,185`; `app/store/repository.cppm:746-751,1239-1243`); duplicate→`ALREADY_EXISTS` via `already_exists` (`repository.cppm:1241`), miss→`NOT_FOUND` (`configs.cppm:98,145,177`). Ephemeral cache removed; error-kind names differ from `DuplicateConfig`/`ConfigNotFound` but status semantics align.
- Extra C++ error paths — DEFERRED — handler still emits `INVALID_REQUEST`/`VALIDATION_FAILED` for malformed body and missing `key`/`value` (`configs.cppm:46,51,56,130,135,140`); upstream surfaces these as `server_wrap` deserialization failures. Not wire-aligned; no external blocker, left as-is.
- Compile-time v1/v2 feature gating — DEFERRED — C++ registers both scopes unconditionally (`configs.cppm:198-294`); `is_v2` only affects path parsing (`configs.cppm:311-321`). Upstream gates scopes at compile time (`routes/configs.rs:11-14`). Runtime dual registration chosen over duplicating build targets; both scopes share one auth scheme per op.
- Broader config subsystem — DEFERRED — out of route scope; upstream `ConfigType`/`DatabaseBackedConfig`/Superposition resolution (`core/configs.rs:67-399`) still not wired to these CRUD routes. Deterministic local substitutes exist elsewhere (`app/services/config.cppm:15,232-252`, `app/handlers/superposition_proxy.cppm`) but remain unconnected to these handlers.
