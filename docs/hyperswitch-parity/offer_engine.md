## Shared contract requests
These need changes outside the two owned files; each is worked around locally and does not change route-level behaviour (wire shape, auth selection, error selection, persistence reads all match upstream).

1. **Merchant account `offer_engine_config` column** — `app::store::merchant_accounts::MerchantAccountRecord` (include/app/store/merchant_accounts.cppm:13-82) has no `offer_engine_config` JSON field and no `get_offer_engine_config()` (upstream config.rs:128-140, api_models/admin.rs:424-432). Worked around by persisting the same JSON under ConfigStore namespace `offer_engine_merchant_config` keyed by merchant id (cppm:688-706). Adding the column + accessor would let `resolve_merchant_offer_config` read the real merchant record.
2. **Dimension config database backing** — upstream `fetch_db_config_for_dimensions`/`fetch_db_config_for_string_enum` (config.rs:19-46) read `state.store` + superposition service; the local `SuperpositionClient`/`ConfigStore` (include/app/services/decision.cppm:281-328, config.cppm:196-364) are in-process substitutes. Config keys are `offer_engine.enabled` / `offer_engine.credential_source` (dimension_config.rs:1285-1322); local namespace `offer_engine` + dimension context mirrors this. No shared change is required for parity.
3. **Auth scheme declarations** — upstream declares `&auth::AdminApiAuth` (routes:23) and `HeaderAuth(ApiKeyAuth{allow_connected_scope_operation:true, allow_platform_self_operation:false})` (routes:46-49). `app/auth/registry.cppm:243-244` holds the local equivalents (`PLATFORM_ADMIN`/`API_KEY` with the two flag slots). Confirm these entries stay stable so the handler's `authorize` checks remain exact.
4. **Microservice HTTP transport** — upstream `OfferEngineClient` uses `hyperswitch_interfaces::MicroserviceClient` with Basic auth, trace header and `base_url` (client.rs:6-48, 132-151). The local in-process backend in ConfigStore (cppm:709-883) is the substitute; a shared microservice client would remove it. The exact outbound request shape is already recorded in ConfigStore namespace `offer_engine_client_requests` (cppm:793-797).
5. **Upstream error code strings** — `core::error::AppErrorKindName` (include/core/error/kind.cppm:33-57) has no `IR_22`/`HE_00` codes; the handler emits the exact `ApiErrorResponse` wire objects locally (cppm:915-941). A shared upstream error envelope would let these use the generic builder.
6. **`error_stack::Report` Debug rendering** — connectivity.rs:48 embeds `{err:?}` of a `Report<OfferEngineError>` in `detail`, whose Debug output includes error-stack frames/source locations that cannot be reproduced byte-for-byte in-process. The handler emits the upstream error variant's Debug form (`MissingApplicationConfig("…")` / `MissingMerchantConfig("…")`, cppm:44-63) with the exact leading text and branch selection (cppm:398-411). No route-level wire difference for valid/configured contexts.
7. **Currency enum validation** — upstream `common_enums::Currency` (api_models/offer_engine.rs:24) rejects unknown codes at deserialization; the local DTO stores the currency as a string on the wire (dto/offer_engine.cppm:69-75) and carries it through unchanged (cppm:496-501, 743-746). Wire shape is identical for valid ISO codes; a shared currency enum with serde validation would close the input-validation gap.
