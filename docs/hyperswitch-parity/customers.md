## Implementation disposition

- v2 base path — SUBSTITUTED — `install()` resolves `micro_services.payment_methods_prefix` from `config_store` with a local default `/v2/customers` and mounts a second scope (`customers.cppm:779-798`); real config population required to drop the default substitute.
- v2 `migrate_global_id` — SUBSTITUTED — `handle_migrate_global_id` parses a text/CSV body into `GlobalIdMigrationRow` results and updates ids via repository; route mounted on v2 scope only (`customers.cppm:687-777,915-926,28-74`); real multipart upload and DB bulk update absent.
- v1 legacy-endpoint access validation — DEFERRED — no legacy-endpoint check in any handler; auth is generic `auth_rules().rule_for(...)` + `authorize_route` only (`customers.cppm:124-128,227-231,457-461,555-559`).
- Document-details / phone-country-code validation — IMPLEMENTED — `validate_customer_fields` + `valid_phone_country_code` called on create and update (`customers.cppm:151-156,496-501,985-1018`).
- Merchant-reference duplicate pre-check — IMPLEMENTED — `repository.find_customer_by_string(customer_id)` returns `ALREADY_EXISTS` before save (`customers.cppm:162-167`).
- Key-manager PII encryption — SUBSTITUTED — `encrypt_pii`/`decrypt_pii` use `AesWrap` with key from `key_store().get("customer_pii","v1")` and fixed local fallback (`customers.cppm:1020-1072,177-185,524-526`); real AES-GCM/vault key manager required; tax id, document details and addresses echoed, not encrypted at rest.
- Address DB insert/update/find — DEFERRED — no address repository calls; address only copied onto responses from the request (`customers.cppm:201-203,537`); needs address-table `StorageInterface` store.
- Merchant-reference fallback / global-id detection — IMPLEMENTED — `locate_customer` falls back to merchant scan and numeric id (`customers.cppm:960-983`); `is_global_customer_id` used in update verify-id and migration (`customers.cppm:953-958,515-520,748`).
- Update verify-id / DB `CustomerUpdate::Update` — IMPLEMENTED — id mismatch check, record copy + field apply, `repository.update_customer` (`customers.cppm:514-532`); domain-model conversion simplified to direct record mutation.
- Delete redaction pipeline — IMPLEMENTED — lock, active-mandate rejection, payment-method removal, encrypted `REDACTED` tombstone, `events().publish`, `process_trackers`, `CUSTOMER_REDACTED` metric (`customers.cppm:579-627`); card/network-token vault deletion remains an external STUB with no local vault store (`customers.cppm:597-598`).
- Mandate retrieval — IMPLEMENTED — `handle_get_customer_mandates` uses `repository.find_mandates_by_customer_id` with merchant filter instead of a static cache body (`customers.cppm:642-685,668-671`).
- List filters / default limit — IMPLEMENTED — query `customer_id`/`time_range` parsing, `parse_time_range`/`within_range`, default limit 10 cited to upstream consts (`customers.cppm:297-331,371-421,1110-1132,334-335,410`).
- v2 OLAP payment-method routes — DEFERRED — owned by the payment_methods domain; `install()` mounts only customer scopes (`customers.cppm:779-798`); no change in this handler.
- Id-type distinction / Sdk+V2Client auth — SUBSTITUTED — id-type via `is_global_customer_id` prefix heuristic (`customers.cppm:953-958`); `SdkAuthorizationAuth`/`V2ClientAuth` paths absent; all handlers use generic `authorize_route` (`customers.cppm:124-128`).
