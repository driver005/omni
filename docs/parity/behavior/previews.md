## Module-level notes

- Ghost treats `/p/:uuid` as a frontend preview (draft) route, not an Admin API route. The api-framework controller is reached only through the frontend proxy (`controllers/previews.js:17,27`), so there is no `mw.authAdminApi` and no `/ghost/api/admin` mount. C++ mirrors this: the route carries no auth and no JSON serde middleware; the `permissions:true` check is performed in-step via `core::auth::ghost` under the frontend proxy's trusted context.
- `headers.cacheInvalidate:false` in `previews.js:59-61` is a *no-header* instruction; the C++ handler writes no cache headers (`handler.cppm:18-31`).
- The only route in this controller is `read`; no `browse`/`add`/`edit`/`destroy` or custom action exists (`previews.js:55-99`), so no C++ route here is EXTRA.
- `forceUrlRelations` is a cross-cutting helper shared with the public/content controllers (`input/utils/url.js:116-141`); previews invokes it directly because it has no input serializer (`previews.js:83-84`). C++ realizes its effect through the store's `include` embeddings (authors/tags/tiers) plus the mapper, using `core::query` for the input pipeline and uuid NQL filter.
- Verdict MATCH is scoped to the `previews.read` endpoint contract that this folder implements; the frontend rendering/redirect layer is documented as a residual gap, not a route-level divergence.
