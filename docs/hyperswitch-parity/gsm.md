## Not ported
None. All four upstream core operations, their transformer conversions, enum validation, error kinds/statuses, wire shapes and both route scopes are implemented in the handler. `LockAction::NotApplicable` has no runtime behavior to port, and `server_wrap`/`#[instrument]` is reproduced by a documented in-process substitute (see Implementation disposition). The only remaining differences are cross-cutting infrastructure items outside the three editable files, listed under `## Shared contract requests`.

## Shared contract requests
- **Error envelope**: the project-wide `AppError` serializes as `{"error":KIND,"message":TEXT}` (`core/error/error.cppm:13-57`), while upstream `ApiErrorResponse` serializes as `{"error":{"type":"IR","code":37|38,"message":...}}` (`api_error_response.rs:684-689`). gsm matches statuses/messages; matching the nested error envelope requires a change to `core/error` (out of module scope).
- **Admin auth header**: upstream `V2AdminApiAuth` parses `admin-api-key=<key>` from the `Authorization` header (`authentication.rs:1744-1766`); the shared `app::auth` `PLATFORM_ADMIN` scheme currently requires a `Bearer` token (`auth/token.cppm:38-63`, `auth/authorizer.cppm:74-78`). Aligning this is an `auth/`-level change.
- **JSON codec leniency**: `core/serde` treats missing required fields as success (`converter.cppm:1198-1217`), so the handler enforces required-field presence via non-empty checks (`gsm.cppm:168-189,563-570`). A DTO-level `#[serde(required)]`-equivalent would remove that manual check.
