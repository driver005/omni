## Implementation disposition

Re-verified 2026-11-20 against `include/app/handlers/webhook_events.cppm`. One line per original `## Not ported` bullet:

- Three `EventListConstraintsInternal` filter variants — SUBSTITUTED — `build_plan` consumes object_id/event_id/is_delivered/recipient/created bounds (`webhook_events.cppm:722-733`) and a single `matches` applies them as scoped in-memory predicates (`:760-807`); replaces three upstream DB-query variants, no per-variant DB query.
- Merchant keystore lookup + event decryption + profile validation — IMPLEMENTED — `event_key` uses `key_store().get` (`:429-436`), `payload_of` decrypts `enc1:` framing via `AesWrap` (`:439-465`), `validate_profile` reads config-store `business_profile` (`:410-427`); hardcoded keystore fallback at `:435` is a documented local substitute.
- 90-day window + created bounds + ordering validation — IMPLEMENTED — `build_plan` defaults `created_after = now-90d`, `created_before = now`, rejects `after > before` (`:735-750`); `matches` applies both bounds (`:789-805`).
- `limit` max-100 validation — IMPLEMENTED — `build_plan` returns `VALIDATION_FAILED` for `limit > 100` (`:711-718`); default remains 100 (`:371`).
- `finalize_event_types` class→type resolution + subset validation — IMPLEMENTED — `finalize_event_types` resolves known classes and rejects types outside the requested class (`:638-698`); called from `build_plan` (`:752`).
- Separate DB `COUNT` for `total_count` — SUBSTITUTED — `list_initial_events` runs a second `list_webhook_events(query)` and uses `counted.size()` (`:831-834`); in-memory length, not a DB COUNT.
- `recipient`/`is_delivered`/`event_classes`/`event_types` store filters — SUBSTITUTED — applied as in-memory `matches` predicates (`:769-788`); only `event_id` and a single `event_type` are pushed into `WebhookEventQuery` (`:823-829`).
- Delivery-attempt lookup by `initial_attempt_id` — IMPLEMENTED — attempts handler compares `initial_attempt_id_of(record, payload)` (`:162`) with chain fallback (`:499-503`); path segment documented as `initial_attempt_id` (`:141`, `:355`).
- Sensitive webhook-header redaction — IMPLEMENTED — `sensitive_header_names` from config-store `webhook_sensitive_headers` with defaults (`:587-622`); `to_retrieve` emits `***REDACTED***` headers (`:924-932`); config list substitutes the upstream business-profile header store.
- Retry ownership check via `initiator_merchant_id` + legacy fallback — IMPLEMENTED — retry handler checks `initiator_of` (`:218-223`), which falls back to `record.get_merchant_id()` when the payload omits it (`:505-509`).
- Retry event construction + idempotency + full field set — IMPLEMENTED — `KeyedHasher.hash_with_domain` idem key + idempotent rescan (`:225-238`), `uuid_v4` (`:240`), `build_retry_payload` with `is_webhook_notified=false`, `initial_attempt_id`, `idempotent_event_id`, `processor_merchant_id`, `recipient` (`:561-585`); keyed hash substitutes upstream `get_idempotent_event_id`.
- Actual webhook delivery trigger + re-fetch — IMPLEMENTED — `events().publish("webhook.delivery.retry")` + `webhook_delivery().enqueue/attempt/retry` (`:265-276`) then `find_webhook_event_by_event_id` re-fetch (`:278-285`); deterministic local delivery through `WebhookDeliveryService` substitutes the real webhook trigger.
- Business-profile lookup on retry + `processor`/`provider` resolution — IMPLEMENTED — retry calls `validate_profile` (`:198-201`); `resolve_processor_merchant`/`resolve_recipient` read config-store keys with payload fallback (`:536-559`); config store substitutes the business-profile lookup.
- Route-level auth detail (JWTAuth variants, granular enum, connected/platform grants, UserFromToken) — SUBSTITUTED — `authorize` delegates to `auth_rules().rule_for(op)` + `authorizer().authorize_route` (`:386-393`), `merchant_from_identity` reads the connected claim (`:395-404`), profile anchored via `validate_profile` (`:410-427`); still flat `AppPermission`, not granular JWTAuth permission enum + grant objects.
- Extra C++ path-prefix tolerance (`id_base`) — DEFERRED — `id_base` still skips `events`/`profile`/`list` segments (`:946-959`); C++-only leniency with no upstream equivalent, deliberately kept for both mount forms.
