## Not ported
- Registered-client lookups/validation `conf.oidc.get_client(...)` on authorize and token: `services/oidc_provider.rs:74-80`, `:149-155`. C++ never checks a client registry (`oidc.cppm:223-229`, `:284-307`).
- `validate_redirect_uri_match` against the registered client URI: `services/oidc_provider.rs:82-85`, `:157-160`; `utils/oidc.rs:25`. C++ only checks non-empty on authorize (`oidc.cppm:226-229`) and equality on token (`oidc.cppm:304-307`).
- Authenticated-user requirement + DB load `find_active_user_by_user_id(user_id)` and `AccessDenied` when no session: `services/oidc_provider.rs:88-98`, `:127-130`. C++ has no user/session concept (`oidc.cppm:231-241`).
- Rich `AuthCodeData` stored in Redis — `sub`, `email`, `is_verified`, `nonce`, `scope`: `services/oidc_provider.rs:103-115`; `types/domain/user/oidc.rs`. C++ caches only the raw authorize payload (`oidc.cppm:237-241`).
- Real authorization response as HTTP redirect via `build_oidc_redirect_url` → `build_redirection_response`: `services/oidc_provider.rs:134-137`; `utils/oidc.rs:35,106`. C++ returns JSON body (`oidc.cppm:244-250`).
- JWKS from real configured keys: iterate `get_all_keys()` + extract RSA public `(n,e)`: `services/oidc_provider.rs:39-62`. C++ synthesizes `n` from a hash and hardcodes `e="AQAB"` (`oidc.cppm:116-125`).
- RS256 signing via configured keys `sign_oidc_token(state, claims, ...)`: `services/oidc_provider.rs:218-221`, `:248-251`. C++ uses static HMAC secret `"oidc-token-signing-secret"` and manual JWT string assembly (`oidc.cppm:319-335`).
- Scope-gated ID-token claims `email`, `email_verified`, `preferred_username` and `nonce`: `services/oidc_provider.rs:202-216`. C++ emits only `iss/sub/aud/jti/iat/exp/typ` (`oidc.cppm:321-330`).
- Token TTL distinction — ID token 15 min vs access token 1 h (`consts/oidc.rs:3-4`, `services/oidc_provider.rs:197-200`, `:229-232`). C++ sets both to 3600 s (`oidc.cppm:318`, `:337`).
- `OIDC_CLIENT_AUTH` on the token endpoint (`routes/oidc.rs:83`) and `validate_client_id_match` on code consumption (`services/oidc_provider.rs:180-182`). C++ authenticates with `USER_WRITE` and never matches a client id (`oidc.cppm:259-262`, `:289-307`).
- Form-encoded token request `web::Form<OidcTokenRequest>` (`routes/oidc.rs:73`). C++ deserializes `application/json` (`oidc.cppm:276-282`).
- `NoAuth` for discovery/JWKS (`routes/oidc.rs:20`, `:35`). C++ requires a USER_READ token (`oidc.cppm:30-33`, `:96-99`) — stricter than upstream and rejects anonymous discovery/JWKS clients.
- Discovery document sourced from `state.tenant.base_url` + control-center base URL (`services/oidc_provider.rs:25-31`, `api_models/oidc.rs:168-191`). C++ hardcodes `https://sandbox.hyperswitch.io` and `https://control-center.hyperswitch.io` (`oidc.cppm:50-55`).
- OIDC API event metrics (`ApiEventsType::Oidc`) on the DTOs: `api_models/oidc.rs:303-331`. Upstream also wraps all flows with `api::server_wrap` + `api_locking::LockAction::NotApplicable` (`routes/oidc.rs:14-22`, `:29-38`, `:47-66`, `:75-86`); C++ uses ad-hoc `metrics().record_flow/counter` only (`oidc.cppm:39-40`, `:105-106`, `:147-148`, `:268-269`).

## Implementation disposition
- Registered-client lookups/validation `conf.oidc.get_client(...)` — SUBSTITUTED — `registered_client_uri()` reads config-store namespace `oidc_client` (`oidc.cppm:562-567`), auto-registers on first authorize and validates on authorize (`:318-324`) and token (`:414-418`); config store stands in for `conf.oidc`.
- `validate_redirect_uri_match` — SUBSTITUTED — redirect URI checked against the registered client on authorize (`oidc.cppm:318-324`) and against both stored code and registered client on token (`:400-403`,`:414-418`).
- Authenticated-user requirement + DB load `find_active_user_by_user_id` — SUBSTITUTED — `authenticated_user_id(req)` resolves sub/headers/bearer (`oidc.cppm:574-590`), FORBIDDEN on empty (`:305-309`), `repository().find_user_by_string` used as the user lookup (`:310-314`); no `find_active_user_by_user_id`.
- Rich `AuthCodeData` in Redis — SUBSTITUTED — `StoredAuthCode` carries sub/email/name/is_verified/nonce/scope/client_id/redirect_uri/state (`oidc.cppm:32-63`) serialized to the injected cache with 300s TTL (`:333-347`); JSON doc replaces Redis hash.
- Real authorization response as HTTP redirect — IMPLEMENTED — `send_redirect` sets status `FOUND` and `Location` header with `code`+`state` (`oidc.cppm:713-734`, called at `:351`); it additionally emits a JSON body for transport clients.
- JWKS from real configured keys `get_all_keys()` — DEFERRED — `oidc.cppm:186-199` still hashes the single `key_store().get("oidc-rsa", ...)` secret (or a UUID) into `n` and hardcodes `e="AQAB"`; KeyStore exposes only `get`/`put` (`:186`,`:537-550`), no key enumeration or RSA `(n,e)` extraction. Remove STUB by adding an RSA key-store enumeration backend. Justified STUB retained.
- RS256 signing via configured keys `sign_oidc_token` — SUBSTITUTED — `token_signer()` builds `app::crypto::JwtSigner` with secret resolver, key id `oidc-signing-key`, namespace `oidc-jwt`, algorithm `RS256` (`oidc.cppm:553-560`, keys seeded at `:535-551`); key material is still a static local secret, and claims are assembled at `:675-711`. Real RSA private-key backend required for true RS256.
- Scope-gated ID-token claims + `nonce` — IMPLEMENTED — `build_claims` emits `nonce`, `email`/`email_verified` under `Scope::Email`, `preferred_username` under `Scope::Profile` (`oidc.cppm:675-711`, gating helper `:667-673`), called for ID token at `:436-439`.
- Token TTL distinction ID 15m vs access 1h — IMPLEMENTED — `id_expires_at = issued_at + 900U`, `access_expires_at = issued_at + 3600U` (`oidc.cppm:431-433`) with separate claim sets (`:436-443`).
- `OIDC_CLIENT_AUTH` + `validate_client_id_match` — SUBSTITUTED — `basic_auth_client_id` parses Basic credentials (`oidc.cppm:592-629`) and matches client id to the consumed code (`:408-413`) plus registered URI (`:414-418`); route auth remains `JWT`/`USER_WRITE` (`registry.cppm:247`), not a dedicated `OIDC_CLIENT_AUTH` scheme.
- Form-encoded token request `web::Form<OidcTokenRequest>` — IMPLEMENTED — `parse_token_request` detects `x-www-form-urlencoded` (or `key=value` body) and parses via `QueryParams`, with JSON fallback (`oidc.cppm:631-665`).
- `NoAuth` for discovery/JWKS — IMPLEMENTED — handler delegates to `auth_rules().rule_for` (`oidc.cppm:517-518`); registry sets `AuthScheme::NO_AUTH` for `oidc_discovery` and `jwks_endpoint` (`registry.cppm:246`,`:190`), invoked at `oidc.cppm:98`,`:164`.
- Discovery document from `state.tenant.base_url` + control-center URL — SUBSTITUTED — `oidc_base_url()` / `control_center_url()` read config store keys `oidc.base_url` / `oidc.control_center_url` with deterministic sandbox defaults (`oidc.cppm:521-533`, used at `:117-123`).
- OIDC API event metrics + `server_wrap`/`LockAction::NotApplicable` — SUBSTITUTED — `counter("oidc.api_event.Oidc")` added on all four flows (`oidc.cppm:105`,`:171`,`:218`,`:367`) alongside `record_flow`; no `server_wrap` or lock action — handler uses direct authorize/respond (`:98`,`:164`,`:211`,`:360`).
