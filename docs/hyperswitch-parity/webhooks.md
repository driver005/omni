## Not ported
- Connector-plugin webhook decoders (`decode_webhook_body`, `get_webhook_event_type`, `get_webhook_object_reference_id`, `get_webhook_api_response`): local in-process substitutes in `webhooks.cppm:891-1003`, `:1017-1029`. Requested on `app::connector::IConnector` below (shared contract request 3). No wire-level difference: the default upstream `get_webhook_api_response` is `StatusOk`, which the local ack reproduces exactly.
- Real payment/refund/dispute/mandate/payout state mutation via connector effects (`incoming.rs:541-566`, `:947`, `:1158`, `:1280`, `:1347`, `:1555`, `:1794`, `:1992`, `:2020`, `:3154`, `:3557`): replaced by the local `WebhookEventRecord` persist + event publish (`:1036-1104`). Observable wire/auth/error behavior is preserved; domain state lives in the local store substitute.
- Kafka broker and superposition/3DS/UAS/UCS services: replaced by `events().publish()` + `config_store()` lookups (`:1064-1104`, `:688-712`). Upstream publishes only metadata, not a wire body (`services/api.rs:323-341`).
- Native labeled metrics (`WEBHOOK_INCOMING_COUNT` with `merchant` dimension, `incoming.rs:194-200`): local counters have no labels, so the dimension is encoded as a keyed-hash suffix (`:1106-1125`). Shared contract request 4.
- Network-token callback mapper (`network_tokenization_incoming.rs:54-70`): no local table; merchant/payment-method ids are read from the webhook payload with `x-merchant-id` as fallback (`:1314-1326`). Shared contract request 5.

## Shared contract requests
1. `include/app/auth/registry.cppm:343-344` registers `receive_incoming_webhook` and `receive_incoming_relay_webhook` with `AuthScheme::HEADER_MERCHANT`; upstream uses path-bound `MerchantIdAuth` / `MerchantIdAndProfileIdAuth`. Request `MERCHANT_ID` scheme entries. The webhooks handler builds typed rules locally in the meantime (`webhooks.cppm:569-589`).
2. `core::error::AppError` serializes to `{"error":KIND,"message":TEXT}` (`core/error/error.cppm:45-57`), not upstream `{"error":{"type","message","code"}}` (`api_models/src/errors/types.rs:37-58`). Request a shared upstream-shaped error type + status mapping. The webhooks handler materializes the upstream shape locally (`webhooks.cppm:77-155`).
3. `app::connector::IConnector` (`include/app/connector/interface.cppm:14-56`) has no `decode_webhook_body`, `get_webhook_event_type`, `get_webhook_object_reference_id` or `get_webhook_api_response`. Request these so webhook handlers can dispatch through connector plugins rather than local marker/substitute helpers (`webhooks.cppm:891-1003`, `:1017-1029`).
4. `app::metrics::MetricsRegistry` counters have no label support; upstream `WEBHOOK_INCOMING_COUNT` is labeled by merchant (`incoming.rs:194-200`). Request labeled counters. Local workaround: hashed-suffix key (`webhooks.cppm:1106-1125`).
5. `app::store::AppRepository` has no callback-mapper table; upstream network-token webhooks resolve `(merchant_id, payment_method_id, customer_id)` through it (`network_tokenization_incoming.rs:54-70`). Request a callback-mapper store record. Local workaround: payload/header fallback (`webhooks.cppm:1314-1326`).
