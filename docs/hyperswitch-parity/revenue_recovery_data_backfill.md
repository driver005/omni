## Not ported
- **utilities**: `get_redis_data` core fn (core:118-155) backing `GET /v2/recovery/data-backfill/redis-data/{connector_cutomer_id}` (app.rs:3568-3570) is not in this handler; it lives in sibling `include/app/handlers/revenue_recovery_redis.cppm:101-104`. Verify separately — not counted as a gap here.
- **cutoff semantics**: upstream passes `cutoff_datetime` into Redis token update so each token's `scheduled_at` older than cutoff is cleared (core:266,312). C++ only stores the cutoff as an ephemeral cache string and never applies it to any token (cppm:176-184).
- **retry-history keys**: upstream parses keys into real `HashMap<PrimitiveDateTime,i32>`, accepting full datetime then date-only fallback (core:335-388). C++ parses into `unordered_map<string,int32>` with no datetime parsing (cppm:460-484). Keys remain raw strings.
- **exp-date failure path**: upstream `parse_expiration_date` error → `build_comprehensive_card_data` error → fallback `ComprehensiveCardData{card_type:"card"}` and the record is still processed (core:269-289,466-523). C++ increments `failed_records` and `continue`s, skipping the record entirely (cppm:87-89,130-133). Counts diverge on malformed exp dates.
- **card-type fallback on missing subtype**: upstream `determine_card_type(None)` returns `None` (core:459-462); fallback card data supplies `"card"` only on build error (core:277-288). C++ leaves `card_type` unset when subtype absent (cppm:72-81). Minor divergence.
- **Redis lock atomicity**: upstream relies on Redis DEL ownership semantics + typed error mapping for wrong-owner / missing-lock (core:71-106). C++ emulates with non-atomic string compare then erase (cppm:359-369) — race condition possible.
- **TTL & masking**: upstream stores secrets via `Secret::new` and real Redis TTLs (core:406-407; storage `RedisTokenManager`); C++ stores plaintext JSON via `to_cache_value` with no TTL (cppm:154-168,282).
- **multipart/form layer**: upstream parses multipart CSV with per-row validation and a `failed_records` list from parsing (routes:24,48; api_models RetryStatsMigrationForm:335). C++ assumes pre-parsed JSON DTOs and never exercises CSV parsing/validation in-process (cppm:47,217,174).
- **retry-stats migration logic**: upstream `migrate_retry_stats_from_csv` (routes:11,91) does cluster-key aggregation in core; C++ simple per-entry cache write, no migration semantics (cppm:224-231).
- **Flow instrumentation / API wrapping**: upstream `#[instrument(Flow::...)]` + `api::server_wrap` + `api_locking` (routes:19,57-71; core flows). C++ substitutes `metrics().record_flow`/counters (cppm:186-189,233-235,306-307,371-372) — observability shape differs.

## Implementation disposition
Re-verified against current `include/app/handlers/revenue_recovery_data_backfill.cppm`. One line per original `## Not ported` bullet.

- **utilities** — DEFERRED — `get_redis_data` remains in sibling `revenue_recovery_redis.cppm:101-104`; this handler registers only 4 routes (cppm:376-425), no redis-data GET. External dependency: sibling handler.
- **cutoff semantics** — SUBSTITUTED — cutoff normalized and applied to each token as `expires_at` (cppm:681,452-459) with a TTL-bounded run marker (cppm:102-107); no per-token comparison clearing `scheduled_at` older than cutoff. Local substitute, not upstream semantics.
- **retry-history keys** — SUBSTITUTED — `normalize_retry_key` parses full-datetime then date-only keys into fixed-width canonical strings (cppm:539-580) and `parse_daily_retry_history` builds the map (cppm:582-613); keys remain strings (DTO limitation), not `PrimitiveDateTime`.
- **exp-date failure path** — IMPLEMENTED — `build_card_data` returns `CardData{card_type:"card"}` fallback on parse error (cppm:637-641); record still counted processed, `failed_records` not incremented (cppm:73-76,95).
- **card-type fallback on missing subtype** — IMPLEMENTED — absent subtype leaves `card_type` unset; `"card"` fallback only on build error (cppm:622-641), matching upstream `determine_card_type(None)`/`build` error behavior. Earlier divergence resolved.
- **Redis lock atomicity** — SUBSTITUTED — `locks().acquire(key, TTL, owner)` (cppm:89-93) and `locks().is_held`/owner check/`locks().release` (cppm:342-365) replace raw string compare-then-erase; `LockRegistry` (app_locking) stands in for Redis DEL ownership, no raw cache erase.

- **multipart/form layer** — DEFERRED — still pre-parsed JSON DTOs `CsvParsingResult`/`RetryStatsMigrationCsvResult` (cppm:50-51,140-141); no in-process multipart CSV parsing/validation. External dependency: upstream multipart form layer.
