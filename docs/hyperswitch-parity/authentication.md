### Route/verb note
Paths and verbs align: upstream scope `/authentication` (`app.rs:3485`) with 7 resources and the dual-verb redirect (`app.rs:3487-3514`); C++ registers 9 `add_route` entries covering the same 8 operations, with `/redirect` POST and GET both bound to `handle_authentication_sync_post_update` (`authentication.cppm:695-718`). Verdict MATCH.

### Input note
C++ DTOs mirror the upstream request field sets, e.g. `AuthenticationCreateRequest` fields (`dto/authentication.cppm:921-937`) vs upstream `AuthenticationCreateRequest` (`routes/authentication.rs:23`); `AuthenticationEligibilityRequest` (`dto/authentication.cppm:971-984`) vs `routes/authentication.rs:54`. Path IDs and client secrets are wrapped into `{"value": ...}` JSON before typed deserialization (`authentication.cppm:384-387,545-548`). Verdict PARTIAL.

### Output note
Wire shape matches upstream DTOs; several fields are now derived rather than hardcoded. Derived: status/transaction_status (`auth_status_from`, `:812-822`), `next_action` URL from auth id + connector reference (`:198`), server/connector transaction ids and CAVV/auth value (`:292-293,508-510`), `created_at` real epoch + id (`:830-836`), eligibility status (`:196,485`). Still synthetic: `three_ds_requestor_url` built from local reference (`:290-291`), `sdk_next_action` enum (`:355-357`), `session_token=ClickToPay` (`:626`), eligibility data enum (`:405-407`), sync amount/currency/profile/email (`:486-495`). Upstream derives all from DB + connector; local connector is a documented deterministic substitute (`:975-980`). Verdict PARTIAL (was STUB).

### Auth note
Upstream mixes `HeaderAuth(ApiKeyAuth{allow_connected_scope_operation:false, allow_platform_self_operation:false})` for create/retrieve (`routes/authentication.rs:40-43,205-208`), `check_sdk_auth_and_get_auth` returning an `auth_flow` for SDK routes (`routes/authentication.rs:62-65,108-112,153-157,232-236,307-311`), and `MerchantIdAuth` for sync_post_update (`routes/authentication.rs:284`). C++ now resolves every operation through `auth_rules().rule_for` + `authorizer().authorize_route` (`:764-773`), derives a flow string from auth claims via `auth_flow_of` (`:775-791`), overrides the body secret with the SDK claim via `effective_client_secret` (`:798-810`, applied at `:173,259,333,448,604`), verifies it against cache/record hash (`:846-875`), and enforces merchant-path match on redirect (`:538-542`). Upstream scope flags and typed `auth_flow` remain unmodeled. Verdict PARTIAL.

### Persistence note
Upstream resolves business profile, encrypts customer details via key manager, generates an `AuthenticationId`, and inserts an authentication record (`unified_authentication_service.rs:718-791`), with later fetches in eligibility/sync/post-sync (`core/authentication.rs:146-162,1070-1083`). C++ now resolves profile via `repository().find_profile_by_string` with metrics (`:61-73`), generates a local id (`:80`), persists and updates an `AuthenticationRecord` through the repository (`:877-906`), fetches it on SDK routes (`:179,266,340,394,448-468,611,861-864,898-904,997-1004`), and caches a client-secret hash (`:838-875`). Customer details use a key-store `LOCAL_XOR` wrap key instead of a real key manager (`:908-930`). Verdict PARTIAL (was STUB).

### Domain logic note
Connector orchestration, trackers, events, and metrics are wired: `schedule_auth_tracker` + `call_connector` + `publish_auth_event` on every mutating route (`:92-99,179-183,266-274,340-344,394-396,471-474,556-560,611-615`); `call_connector` selects a connector via `connector_router().select_for` and dispatches `sync`/`verify`/`authorize` through process trackers (`:947-981,932-945`). No real 3DS PSP backend is registered, so a deterministic local outcome is produced (`:975-980`). v1 UCS proxy flows and the separate 3DS version call are absent. Verdict PARTIAL (was STUB).
