## Not ported
- `OfferEngineClient` network calls: `browse_offers(&state, list_request)` `/list` and `check_connectivity(&state)` (browse.rs:70-75, connectivity.rs:58-61). C++ has no client wired; comments state "connectivity probe is not wired in this deployment" (cppm:65, 72-73, 155-157).
- Offer eligibility filtering: response drops entries where `status != OfferStatus::Eligible` and maps via `BrowseOffer::from` (browse.rs:79-84). C++ returns `offers:{}` (cppm:159-160).
- DB-backed dimension config resolution via `fetch_db_config_for_dimensions` / `fetch_db_config_for_string_enum` with `state.store` + superposition service (config.rs:19-46). C++ uses ephemeral cache keys `offer_engine.config.<scope>.<field>` with no persisted config entity (cppm:220-246).
- Merchant credentials from `merchant_account.get_offer_engine_config()` parsed as `OfferEngineMerchantConfig` (config.rs:111-147). C++ reads api key from cache (`merchant_api_key`, cppm:270-277) and acknowledges "no C++ store record" (cppm:140-141).
- Application config resolution: `state.conf.offer_engine` `api_key`/`merchant_id`/`base_url` (config.rs:75-108). C++ reads only a cached api key (cppm:262-268); no merchant_id/base_url resolution.
- Profile-scoped dimension lookup: upstream resolves dimensions with `with_profile_id(profile_id)` when auth carries a profile (browse.rs:36-42, routes/offer_engine.rs:43-44). C++ builds a scope string from header merchant + `auth.profile_id()` (cppm:120-121, 248-260); not equivalent to typed dimensions.
- Auth semantics: `AdminApiAuth` and `HeaderAuth(ApiKeyAuth{...})` with connected-scope / platform-self flags (routes/offer_engine.rs:23, 46-49). C++ substitutes `AppPermission::ADMIN`/`PAYMENT_READ` and boolean flags via `authorize()` (cppm:34-40, 92-98).
- Merchant-not-found 404 is added behavior: C++ calls `find_merchant_account_by_string` (cppm:124-132); upstream `browse_offers` has no merchant existence check, mapping config failure to `AccessForbidden { resource: "offer_engine" }` (browse.rs:44-64).
- Other core modules unported: `amount`, `apply`, `eligibility`, `notify`, `velocity`, `client`, `types` (core/offer_engine.rs:1-12). C++ installs only the two routes (cppm:168-195).
- Offer domain types: `OfferStatus`, `BrowseOfferListRequest/Response/Entry`, `BrowseOfferRules`, `BrowseOfferAmount` (types.rs:91, 336-370) absent from C++ DTO; currency filter is parsed but discarded (cppm:155-157).
- Flow instrumentation / API locking: upstream `Flow::OfferEngineConnectivityCheck`/`OfferEngineBrowseOffers` and `LockAction::NotApplicable` (routes/offer_engine.rs:16, 24, 36, 50). C++ only records metrics counters (cppm:78-79, 163-164).

- `OfferEngineClient` network calls — SUBSTITUTED — browse via `connector->check_feature_matrix` (cppm:231-237) and connectivity via `connector->verify` in `probe_connectivity` (cppm:406-442) over the connector router; real network client needs external endpoint/credentials (browse.rs:70-75, connectivity.rs:58-61).
- Offer eligibility filtering — SUBSTITUTED — filter loop drops `status != "Eligible"` and maps survivors to `BrowseOffer` (cppm:256-276); status comes from local `eligibility_status` decision-engine substitute (cppm:444-463), not upstream offer payload status.
- DB-backed dimension config resolution — SUBSTITUTED — `config_value` uses `superposition().resolve` then config_store scoped/base keys (cppm:369-383), scope built by `dimension_scope` (cppm:331-357); no persisted `state.store` config entity, requires DB config records to remove substitute (config.rs:19-46).
- Merchant credentials from `offer_engine_config` — SUBSTITUTED — secret resolved via `api_key`/`config_value` (cppm:385-388, 369-383); comment states no merchant_account store record, secret persisted as dimension-scoped config record instead (cppm:193-197). Real `merchant_account.get_offer_engine_config` needs DB record (config.rs:111-147).

- Auth semantics — SUBSTITUTED — `authorize` delegates to `auth_rules().rule_for` + `authorizer().authorize_route` (cppm:322-329) with registry flags documented at cppm:96-97, 160-162; substitutes upstream `AdminApiAuth`/`HeaderAuth(ApiKeyAuth{...})` (routes/offer_engine.rs:23, 46-49).
- Merchant-not-found 404 added behavior — IMPLEMENTED — 404 branch removed; config failure maps to `FORBIDDEN` "Access forbidden for resource offer_engine" (cppm:199-208), matching upstream `AccessForbidden` mapping (browse.rs:44-64).
